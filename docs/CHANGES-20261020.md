- **PDF/ZIP 增加 `suspicious_structures` 支持（#18 / A-13，`adapters/zip.rs` / `adapters/pdf.rs`）**：
  - ZIP：在 `pre_cd_inject` 策略下通过 CD 起始偏移前 24 字节解析信封尾部，以 `ube_offset + ube_total_size == cd_offset` 且 `ube_total_size >= 136` 做无口令结构告警；在 `eof` 策略下通过 EOCD 后的尾部 24 字节判定 `ube_offset + ube_total_size == file_size`。防止对已有 stealth 信封的 ZIP 进行无知觉二次叠加覆盖。
  - PDF：在 `incremental` 增量流对象结尾 `endstream` 前 24 字节以 `ube_offset + ube_total_size == stream_end` 且前导 `stream` 关键字验证候选信封；在 `eof` 策略下检测最后 `%%EOF` 之后的附加尾部。
  - 顺带修复 `adapters/mp4.rs:402` 在 `suspicious_structures` 中裸加法导致 debug 溢出 panic 的隐患（改用 `checked_add`）。
- **`decrypt_metadata` 错误语义解耦（#19 / A-15，`crypto.rs` / `engine.rs`）**：
  - `crypto::decrypt_metadata` 底层解密认证失败时返回 `CorruptedData`，由上层调用方根据上下文处理：`read_carrier` 中仅在 `header.is_encrypted()`（且传了密码）时将解密失败映射为 `StrHideError::Password`；对于未加密载体（使用内置默认密钥），解密失败按 `CorruptedData` 报告，彻底消除未加密文件损坏时误报"Password error"的误导问题。
- **PE `pe_codebits` 消除重复 profiling（#20 / A-10a，`adapters/pe_codebits.rs`）**：
  - 提取 `parse_channel_header_from_profile`，使 `extract_ube` 与 `apply_diff` 只需调用一次 `profile(text, bitness)` 即可同时完成 Header 校验与指令比特翻转，反汇编和指令扫描耗时直接减半。
- **PE `-s eof` 归因修正（#21 / P2-1，`engine.rs`）**：
