#### P0-2 结构域信封的物理边界与认证边界

- `structure/engine.rs`：新增 `confine_location()`，在 `locate_envelope_with_magic` 这个唯一入口校验
  `ube_total_size >= 112 + 24` 且 `ube_offset + ube_total_size <= 文件长度`；不满足即视为"无信封"。
  此前 PE `pe_overlay` 与 MKV `ebml_void` 只校验起点，伪造 trailer 可声明 1 TiB 信封。
- `structure/adapters/pe.rs` / `mkv.rs`：追加型策略补 `ube_offset + ube_total_size == 文件长度` 等式。
- `structure/envelope.rs`：新增 `MAX_META_LEN = 256 KiB` 并在 `validate_against` 中拒绝更大的 `meta_len`；
  读取侧不再可能按不可信字段申请 GiB 级缓冲。
- **AAD 扩展**：新增 `EnvelopeHeader::auth_aad(hint)`，AEAD 的认证集合变为
  `header[0..80] || meta_len || hint_len || hint`。`meta_len`/`hint_len`/提示正文因此被认证；
  写入端在密封前就填好 `meta_len`（= 明文 + tag），读取端与 `inspect` 统一走同一构造。
- `core/crypto.rs`：`encrypt_metadata` / `decrypt_metadata` / `encrypt_stream_to_chunks` /
  `decrypt_stream_from_chunks` / `verify_payload_stream` 的 `aad` 参数由 `&[u8; AAD_SIZE]` 改为 `&[u8]`
  （分块 AAD 缓冲按实际长度分配）。

#### P0-3 加密信封后 32 字节与明文 hint

- 提示正文进入 AAD（见上），篡改提示会同时破坏元数据块与全部分块 tag；新增
  `tampered_hint_breaks_authentication` 覆盖"改一个提示字节 → read/verify L3 必须失败"。
- 四个注入后坐标（`inject_offset` / `inject_size` / `patch_offset` / `orig_patch_val`）确认**无法**进 AAD
  （密封发生在注入之前），改为三条结构兜底：物理包含、`inject_offset + offset_delta == trailer.ube_offset`
  （`offset_delta` 在 AAD 内）、`remove` 用认证过的 `orig_host_sha256` 复核还原结果。
- 修正三处错误注释：`engine.rs` 写侧"AEAD authenticates it"、`pack_masked` 的 `None` 语义、
  `unpack_with_secrets` 的裸 header 分支；`pack_masked`/裸 header 保留不掩码，理由改为真实原因
  （无密码时必须能识别出"需要密码的信封"，否则 `PasswordWithHint` 与提示永远不可达）。
