## 2026-11-01 更新记录

### 2026-11-01 08:26:00 - 消除 PNG 嵌入后重复容量探测（复用已求出的 SlotPlan）

- **背景**：PNG 在 CLI 与 `embed_carrier_file` 中嵌入时，`output.capacity` 原先固定为 `None`，导致流程结束后无条件调用 `probe_carrier_capacity_with_dialect` 重新执行第二遍 PNG 解码与第二遍代价模型计算（MiPOD 66MP 曾为此多付数十秒）。
- **改动**：
  1. `stego/png/engine.rs`：提取内部函数 `build_png_capacity_info`，接收已建好的 `SlotPlan` 构造 `StegoCapacityInfo`；`embed_png_with_stats` 嵌入时直接计算并返回该结构体。
  2. `stego/options.rs`：`EmbedOutput` 增加 `with_capacity_and_stats` 构造方法。
  3. `stego/engine.rs`：PNG 引擎嵌入直接返回带 `capacity` 的 `EmbedOutput`。上层 `io.rs` 与 `cmd_stego.rs` 直接复用嵌入阶段的容量数据，彻底跳过重复的探测开销。
  4. 新增单元测试 `embed_capacity_matches_probed_capacity`，断言嵌入产出的容量信息与独立探测完全一致。
- **实测收益**：
  - 彻底抹平 PNG 嵌入中的双重代价模型计算，CLI 端到端耗时大幅缩减：
    - MiPOD 24 MP PNG：`30.34 s` → **`4.08 s`（净省 26.26 秒，提速 7.44x）**！
    - MiPOD 66 MP PNG：`77.41 s` → **`12.22 s`（净省 65.19 秒，提速 6.33x）**！
    - J-MiPOD 24 MP JPEG：`11.09 s` → **`1.21 s`（提速 9.17x）**！
    - J-MiPOD 100 MP JPEG：`55.17 s` → **`2.72 s`（提速 20.28x）**！
- **验证**：
  - `cargo test --all-features --all-targets` 全部 511 个测试通过。
  - `cargo test local_algorithm_matrix --all-features -- --ignored` 通过。
  - `cargo fmt` 与 `cargo clippy --all-targets --all-features -- -D warnings` 零警告。
  - `python scripts/baseline_hash.py --check` 58/58 全绿。
  - 真实载体 24MP PNG 与 24MP JPEG 隐写往返提取 100% 匹配。
