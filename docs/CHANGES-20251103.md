## 20:22:21 — HEVC 引擎接入 V4 内容信封（Step 8）

- `stego::hevc::engine`：`embed_hevc*` / `extract_hevc_v4` / `inspect_hevc_v4` / `inspect_hevc_mp4_file_v4` / `verify_hevc_v4` 全部切到 V4；新增 `HevcSuperblockV4`（32B：magic4、version/flags、stc_u、window_slices、ext_len、suite_id、body_len、header_crc32、nonce12），沿用 524 基础槽，扩展区 `hevc_extension_slots(ext_len)=2*(8*ext_len+6)`。
- 长度语义统一：`body_len` = AEAD 密文长度（含 16B tag）；容量公式写死为 `message_bits(total_slots - hevc_header_slots(ext_len))/8 - BODY_OVERHEAD`，删除 `HEVC_TAG_BYTES` / `fmt.header_bytes + 1` 旧口径；recommended 同式。
- 顺序：Header 解码/CRC → `header_slots` 载体上界 → 扩展 TLV → `validate_header`（suite/`body_len`/header_slots）→ L3 session → Body 槽位与 budget → AEAD；全部失败折叠为 `NoHiddenData`。
- **body 排列密钥化**：此前 body 用固定 Weyl 步长，`perm_seed` 只影响 `superblock_positions`。现在 `band_positions` 按 band 用 `keyed_band_params(len, perm_seed, band.start)` 派生 `(start, stride)`（32B seed 顺序折叠进 SplitMix64，stride 与 len 互质），`perm_seed` 真正作用于 body 槽位；`superblock_positions` 与扩展区共用同一 keyed 前缀排列。
- HEVC magic 仍由 L2 `derive_l2_locator_keys(..., magic_label)` 派生（keyed）；nonce 作为 L3 session salt：`SHA-256("strhide-hevc-session-v4" || nonce)`；AAD = `build_v4_aad(HEVC_FORMAT_ID=5, header32, extension)`。
- `pre_salt` 只用不可变元数据：`SHA-256(fmt.cover_salt || "hevc-v4" || parameter-sets digest)`，Annex-B 走 span 摘要。
- 清理：删除 V2 `HevcSuperblock`、`derive_magic`、`derive_hevc_key`、`trellis_seed_from_key`、`effective_secret`、`check_header_bytes`、`HEVC_TAG_BYTES`；`HevcFormatProfile` 移除 `kdf_info`/`header_bytes`。
- 修复：扩展区读取把槽数（`hevc_extension_slots`）误当消息位数，导致非空扩展时 `extract` 恒失败；改为按 `ext_bytes * 8` 取消息位。
- 测试：新增 `header_tamper_with_recomputed_crc_is_rejected_by_aead`、`superblock_v4_*`、容量公式、扩展 AAD、TLV criticality、keyed/前缀稳定排列单测；`tests/test_media/hevc_stego.rs` 新增 `test_hevc_v4_extension_probe_matches_embed`（probe==embed、错误口令折叠）与 `test_hevc_v4_truncated_body_is_rejected`（载体截断不得提取）。`max_pbkdf2_iterations` 仍临时 2,000,000，V4 显式 200k 且 L1 前拒绝 <200k。
