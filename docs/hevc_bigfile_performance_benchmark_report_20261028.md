## 5. 核心指标与优化方案实测对比

```
[嵌入耗时 (ms)] 对比 (越低越好)
优化前 (全片解码): |████████████████████████████████████████| ~180,000 ms (3 分钟)
优化后 (16 B 载荷): |▎| 1,203 ms
优化后 (1 KiB 载荷): |▎| 1,234 ms
优化后 (16 KiB 载荷): |▍| 1,329 ms
优化后 (64 KiB 载荷): |▌| 1,828 ms
优化后 (256 KiB 载荷): |█▎| 4,264 ms

[内存峰值 (MB)] 对比 (越低越好)
优化前 (载体 529MB): |████████████████████████████████████████| ~50,000 MB ~ 68,000 MB (OOM 崩溃风险)
优化后 (提取阶段):   |▍| 590 MB (堆占用仅 ~60 MB)
优化后 (嵌入阶段):   |▋| 1,064 MB (零重复堆拷贝，仅内核 copy + 补丁原位覆盖)
```

1. **流式分窗隐写协议 (Scheme C v2)**:
   - 提取时无需全片解码 3.4 万个切片，微载荷（16B~1KB）仅需解码极少量切片，耗时由 **180 秒缩短至 0.5~1.4 秒**（提升 **120 倍**）。
   - 错密码或空载体探测时，前 2048 槽位快速识别，早退耗时稳定在 **0.5~0.8 秒**（含全量 MP4 容器解析）。
2. **零堆内存增量补丁提交 (`commit_carrier_patches`)**:
   - 529 MB 大视频在隐写过程中，严格免去了构造第二份 529 MB 完整 `Vec<u8>` 的堆内存分配。
   - 磁盘写入仅对被修改的切片进行局部原位 seek 覆盖（仅修改几 KB 到几十 KB），消除了 529 MB 的磁盘全盘重复写入。
3. **多核并行切片重编码与 EPB 检查 (`rayon`)**:
   - 256 KiB 超大载荷涉及数十个切片的翻转重编码，多核并行计算在 4.2~4.6 秒内即全部完成。
4. **视频合规与画质无损保证**:
   - 使用 `FFmpeg 8.1.2` 对生成的 16B 及 256KB 隐写视频执行全片 24 分钟共数万帧的完整解码校验，**0 报错、0 警告、0 坏帧**，完美兼容各大播放器和流媒体工具。

## 7. 视频流式分窗稀疏度与安全档位校准

针对多帧视频载体中前部切片载荷集中度对局部画质的影响，基于 Netflix VMAF 模型、SSIM 及 PSNR 评测，校准了 `VideoBudget` 的三个安全档位：

| 安全档位 (`--safety`) | `non_ref_fraction` | 空间稀疏度因子 | 适用场景与质量指标 |
| :--- | :--- | :--- | :--- |
| `paranoid` (0) | **0.1** | **10.0x** | 超高保真档：单帧扰动极低，VMAF > 98，PSNR avg > 68 dB |
| `high` (1, 默认) | **0.2** | **5.0x** | 默认推荐档：均衡画质与扫描开销，VMAF > 97，SSIM > 0.999 |
| `balanced` (2) | **0.4** | **2.5x** | 平衡档：较高载荷承载能力，放不下时由用户显式指定 |

### 门控与容量保护机制
1. **放不下即报错拦截**：在视频载体嵌入时，若载荷在当前档位所需的稀疏槽位数超出载体可用总槽位，系统主动抛出容量不足错误，并友好引导用户切换到更宽松档位（如 `--safety balanced`）或削减载荷；
2. **静图与视频模型隔离**：单张静态图片（HEIF/单帧 Annex-B）维持原生单图容量模型，不受多帧视频稀疏度分窗限制。

## 8. 结论

通过分批实施的 5 项核心优化方案：
1. **彻底攻克了 HEVC 大视频（数百 MB、数万切片、数亿槽位）隐写时内存暴涨与 OOM 的历史隐患**，常驻堆内存净开销从数十 GB 压缩至几十 MB；
2. **中小型常见载荷的处理时间缩短了 1~2 个数量级**（从数分钟进入秒级体验）；
3. **载荷提取 100% 位精确无损还原**，隐写后 MP4 视频保持**严格 0 字节体积膨胀**并通过 FFmpeg 全片解码验证；
4. **校准了视频安全档位稀疏度（0.1/0.2/0.4）与门控保护**，兼顾大文件秒级处理与高保真感知画质。
