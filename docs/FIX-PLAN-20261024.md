## 一、 审查结论真伪核对与裁定总览

经过逐行对照 `rust/` 源码（共 64 个源码文件）、核查算法数学原理（RS、HILL、UERD）及运行回归测试，对三份评审提出的问题裁定如下：

### 1. 真实且高价值修复（确定采纳，纳入 Fix Plan）
- **[算法纠错] RS 隐写分析负掩码算子写错（gem P0-1）**：`RsMask::Minus => w[4] + 1` 为严重笔误，破坏了负向对合置换对称性，导致拟合曲线参数失真。
- **[数据可用性] 空间域提取忽略 FeatureWord 中的 `exclusion_permille`（wb P1-4 / glm 4 / gem P0-5）**：非默认 `--exclusion-rate` 嵌入的文件，提取时必因 slot 集合错位而失败。
- **[安全与不变量] PE `pe_codebits` 恢复端缺失 padding 范围校验（wb P2-8 / glm 2 / gem P0-2）**：恶意载体未校验 `slack_off`，直接清零指定偏移数据。
- **[溢出与 DoS] ISO BMFF box 遍历 u64 回绕死循环（wb P1-1 / glm 1 / gem P0-3）**：畸形 `largesize` 裸加法导致 `offset` 回绕为 0，陷入死循环挂死。
- **[溢出与崩溃] PDF `/Size` 增量更新 u64 溢出（wb P2-5 / glm 3 / gem P0-4）**：畸形 `/Size` 加 1 导致 debug panic 或 release 生成损坏 PDF。
- **[溢出与崩溃] MKV EBML `header_len + data_size` 裸加法溢出（gem P0-6）**：括号内未受检加法在超大 VINT 时直接 panic。
- **[边界鲁棒性] 7 处 trailer 校验裸加法（wb P2-1）**：多处未统一使用 `checked_add`。
- **[数据可用性] ZIP strip 首段拷贝静默截断（wb P2-2 / glm 13）**：流读取提前中断时静默返回 `Ok`，违背 100% 还原契约。
- **[崩溃防御] PE `pe_codebits` 短 UBE 切片越界 panic（wb P2-3）**：`debug_assert` 在 release 失效，裸索引存在 underflow panic 隐患。
- **[静默错位] PE `pe_slack` inject 误用 `copy_stream`（wb P2-4）**：流截断时写入字节不足导致后续数据错位。
- **[API 加固] 空间域三个公开入口未校验 `SpatialParams`（wb P1-3）**：传入偶数窗口在 HILL 切片计算中 panic。
- **[DoS 防御] 空间域 extract 依据未认证头字段预分配超大 Vec（wb P1-2）**：恶意头声称超大长度导致 12.8GB 一次性分配 OOM/Abort。
- **[溢出防御] UERD / Calibration 中 `i16::MIN.abs()` 溢出 panic（gem P0-7）**：debug 下直接 panic，应使用 `unsigned_abs()`。
- **[数值防御] UERD 量化表步长未做 `max(1)` 防御（wb P3-5）**：存在除以 0 或 0 代价风险。
- **[CLI 一致性] CLI 密码处理 `-p ""` 与 `--password-file` 多行处理（wb P2-13 / glm 5,6 / gem 15,16）**：空密码被静默接受，密码文件未取第一行。
- **[性能优化] `CompressionStrategy::Never` 仍执行全量压缩（wb P2-15 / glm 8）**：已声明不压缩仍跑 Deflate。
- **[性能优化] Calibration 盲校准双重循环内的二次全表扫描优化（gem P1-10）**：378 次外层扫描重复遍历 blocks，应改为单趟直方图统计（百倍提速）。
- **[性能优化] S-UNIWARD 垂直卷积跨行访存循环重排（gem P1-9）**：消除最内层大跨度跨行 Cache Miss，使能连续向量化。
- **[数值精度] Wiener 降噪局部方差消除巨量消除（gem P1-8）**：平滑区域两数相减尾数坍塌，改用中心残差平方和。

### 2. 澄清驳回的评审项（经源码与文献核对判定为误报或不宜改动）
- ❌ **驳回：“HILL 代价函数倒数位置提前在两级低通之间、缺末级 KB3”**（wb P2-7 / glm 11）
  - **实证**：比对官方 MATLAB 实现，HILL 算法流程为：$H_1$ 高通滤波 $\to$ $H_2$ 低通滤波（$p_1 \times p_1$） $\to$ 取倒数 $W = 1./(R_{smooth} + \epsilon)$ $\to$ $H_3$ 低通滤波（$p_2 \times p_2$）。
  - **结论**：当前 Rust 代码与官方 MATLAB 源码完全一致。评审者将 $H_1$ 高通滤波误当成了低通，误以为有两次连续低通。**该项为误报，严禁修改，否则将破坏与官方算法的保真度。**
- ⚠️ **暂不采纳：“UERD 邻域权重均值改求和”**（wb P2-9）
  - **实证**：使用均值是考虑到图像边缘不同邻域块数量（3/5/8）所作的归一化平滑。改动权重将改变已有 carrier 的代价分布，且两端本就对称无数据损坏。保持现状。
- ⚠️ **暂不采纳：“大文件全流式解密重构”**（gem P1-11）
  - **实证**：需重构引擎层与加密层接口，改动面大，不符合“改动小、风险低”原则，列入长期架构演进。
- ⚠️ **暂不采纳：“引入 zeroize 并在 drop 时清零敏感密钥”**（wb P2-6 / gem 14）
  - **实证**：需添加新依赖并移除 `PasswordSecrets` 的 `Copy` trait，涉及大量调用点签名改造，单独立项处理。
- ⚠️ **暂不采纳：“修改空间域头排列慢 KDF 派生”**（wb P1-5）
  - **实证**：会导致 wire format 不兼容（Bump Wire Format），不属于低风险轻量修复。

## 二、 修复方案与计划（按“改动小、收益大、风险低”排序）

### 第一阶段：边界加固与数据可用性修复（改动极小，立竿见影）

#### 1. 空间域 extract 适配 FeatureWord 的 `exclusion_permille`
- **问题文件**：`rust/src/stego/spatial/engine.rs:1366-1370`
- **修复方案**：在 extract 端解析出 `fw` 后，用载体自描述的 `fw.exclusion_permille` 覆盖 `params.exclusion_percentile`，再调用 `SlotPlan::build`。
- **代码变动**：
  ```rust
  let mut effective_params = *params;
  effective_params.exclusion_percentile = (fw.exclusion_permille as f64) / 1000.0;
  let costs = resolved.compute_cost(&image.pixels, w, h, image.channels, &effective_params);
  let plan = SlotPlan::build(&image, &costs, &effective_params, password, domain, spatial)?;
  ```
- **测试验证**：新增测试：使用 `--exclusion-rate 0.45` 嵌入，使用默认参数（0.3）提取，验证能否成功解码。

#### 2. PE `pe_codebits` 恢复端 padding 范围校验
- **问题文件**：`rust/src/adapters/pe.rs:718-738`
- **修复方案**：在 `read_at` 和 `copy_with_patches` 清零前，检查 `[channel.slack_off, channel.slack_off + diff_len)` 是否完全包含在 `layout.slack_ranges` 内（与 `pe_slack.rs` 对齐）。
- **代码变动**：
  ```rust
  let inside = layout.slack_ranges.iter().any(|&(s, e)| {
      let start = channel.slack_off as u64;
      let end = start + diff_len as u64;
      start >= s && end <= e
  });
  if !inside {
      return Err(StrHideError::CorruptedData(format!(
          "pe_codebits slack region [{:#x}, +{}) is not within PE padding",
          channel.slack_off, diff_len
      )));
  }
  ```
- **测试验证**：单测构造非法 `slack_off`，验证 `strip_codebits` 立即拒绝。

#### 3. ISO BMFF `largesize` u64 回绕防御与循环计数上限
- **问题文件**：`rust/src/adapters/isobmff.rs:183, 232`
- **修复方案**：改用 `checked_add`，若溢出或超过 `total_size` 则返回格式损坏错误；增加循环最大迭代次数限制（如 1,000,000）。
- **代码变动**：
  ```rust
  let next_offset = offset.checked_add(box_size)
      .filter(|&o| o <= total_size)
      .ok_or_else(|| StrHideError::CorruptedData(format!(
          "Box {} at offset {box_offset} extends past EOF or overflows",
          String::from_utf8_lossy(box_type)
      )))?;
  offset = next_offset;
  ```

#### 4. PDF 增量更新 `/Size` 溢出防御
- **问题文件**：`rust/src/adapters/pdf.rs:223, 511`
- **修复方案**：在解析 trailer 或 xref 后，对 `new_obj_num` 增加合法性上限校验（`new_obj_num < 0x7FFF_FFFF`）。

#### 5. MKV EBML `header_len + data_size` 裸加法溢出修复
- **问题文件**：`rust/src/adapters/mkv.rs:201`
- **修复方案**：改用链式 `checked_add`，杜绝括号内裸加法溢出 panic。

#### 6. 7 处 trailer 校验裸加法防御
- **问题文件**：`zip.rs:258`, `png.rs:224`, `jpeg.rs:409`, `pdf.rs:601`, `mkv.rs:161`, `riff.rs:225, 167`
- **修复方案**：统一替换为 `.checked_add(...) == Some(file_size)`。

#### 7. `zip.rs` strip 首段拷贝静默截断修复
- **问题文件**：`rust/src/adapters/zip.rs:281-289`
- **修复方案**：删除原有的截断 while 循环，直接调用 `crate::adapters::io::copy_exact(stego_in, out, header.inject_offset)?;`。

#### 8. PE `pe_codebits` / `pe_slack` 流与切片防御
- **问题文件**：`pe_codebits.rs:595-601`, `pe_slack.rs:90`
- **修复方案**：
  - `pe_codebits.rs`: `let magic = *ube.last_chunk::<4>().ok_or_else(|| StrHideError::CorruptedData("UBE too short".into()))?;`
  - `pe_slack.rs`: 改用 `copy_exact(ube_in, out, ube_size)?;`。

#### 9. 空间域三个公共入口补齐 `params.validate()?`
- **问题文件**：`rust/src/stego/spatial/engine.rs:985, 1273, 1473`
- **修复方案**：入口处增加 `params.validate()?;`。

#### 10. 空间域 extract 预分配防护 (DoS 防御)
- **问题文件**：`rust/src/stego/spatial/engine.rs:910, 1396`
- **修复方案**：先执行 `let pool = plan.count_body_slots(&image, fw.class_rule, mode); if needed_body_slots > pool { return Err(no_hidden()); }`，并在 `body_slots_upto` 内限制 `limit.min(pool)`。

### 第二阶段：算法修复与 CLI/体验加固（关键逻辑纠偏）

#### 11. RS 隐写分析负掩码变换算子纠正
- **问题文件**：`rust/src/analysis.rs:1697-1700`
- **修复方案**：纠正 `RsMask::Minus` 算子为标准的负向对合置换：
  ```rust
  RsMask::Minus => {
      let x = w[4];
      if x & 1 == 0 {
          (x - 1).max(0)
      } else {
          (x + 1).min(255)
      }
  }
  ```
- **测试验证**：运行 `cargo test rs_`，并增加针对合成平滑图与带隐写图的回归测试。

#### 12. UERD / Calibration `i16::MIN.abs()` 防御与量化步长 clamp
- **问题文件**：`stego/jpeg/cost/uerd.rs:77, 88`, `analysis/calibration.rs:147`
- **修复方案**：
  - `uerd.rs`: `coeff.unsigned_abs() as f64`，量化步长 `geometry.luma_q[i].max(1)`。
  - `calibration.rs`: `b[mode].unsigned_abs() == value as u16`。

#### 13. CLI 密码处理一致性增强
- **问题文件**：`rust/src/cli.rs:658-695`
- **修复方案**：
  - `-p` 与 `--password-file` 若为空字符串，明确返回 `StrHideError::Password("Password cannot be empty")`。
  - `--password-file` 取首行：`s.lines().next().unwrap_or_default()`。
  - `STRHIDE_PASSWORD` 执行 `trim_end_matches(&['\r', '\n'])`。

#### 14. `CompressionStrategy::Never` 避免无谓 Deflate 压缩
- **问题文件**：`rust/src/engine.rs:926-933`
- **修复方案**：若为 `Never`，直接短路返回 `(payload_raw_bytes, false)`。

### 第三阶段：性能与精度优化（改动安全、无损提速）

#### 15. Calibration 盲校准双重循环内的二次全表扫描优化
- **问题文件**：`rust/src/analysis/calibration.rs:247-269`
- **修复方案**：将原本 $378 \times 4 \times N$ 次全量扫描重构为单趟直方图统计：
  - 遍历一次 `luma_blocks` 统计 `[u32; 64][16]`；
  - 遍历一次 `calib` 统计 `[u32; 64][16]`；
  - 外层 378 次循环直接 $O(1)$ 查表计算。
- **收益**：校准分析耗时缩短 99%，结果 100% 保持一致。

#### 16. S-UNIWARD 垂直卷积跨行访存优化
- **问题文件**：`rust/src/stego/spatial/cost/suniward.rs:164-174, 203-213`
- **修复方案**：将 `a` 抽头循环移至外层，中层遍历 `y`，内层按行连续累加切片，消除 Cache Miss 并启用 SIMD 向量化。

#### 17. Wiener 降噪局部方差数值精度优化
- **问题文件**：`rust/src/stego/jpeg/cost/precover.rs:152-155`
- **修复方案**：先计算局部均值 $m$，再两趟累加 $(v - m)^2$，根除浮点数巨量消除。
