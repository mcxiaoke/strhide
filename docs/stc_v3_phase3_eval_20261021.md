# STC-V3 Phase 3 评测报告：参数网格、失真与可检测性

> **评测时间**：2026-10-21 23:20
> **代码基线**：STC-V3 Phase 2 完成后的工作树（`rust/`，commit `af270e9` 之后）
> **评测脚本**：`rust/examples/v3_eval.rs`（参数网格）、`tests/batch_stego.rs`（语料回归）、`src/analysis/calibration.rs`（标定估计）
> **语料**：`temp/images/jpg` 80 张真实相机照片（1920×1280 4:2:0 等），`temp/teststego` 19 张混合载体
> **结论**：默认参数定为 `h = 8`、`slot_budget = 1,200,000`；极化折价保持关闭（1.0）；标定检测阈值 0.09 → 0.05。

### 1.4 选型结论

- **`h = 8`**：`h = 6/7/10` 在同预算下改动数更多或没有改善，而 `h = 10` 在 4 KiB 上已 **3.5 s**，超过"耗时 ≤ 3 s"的门禁。
- **`slot_budget = 1,200,000`**：三档载荷下失真、PSNR、体积增幅全面优于 400k/800k，耗时仍 ≤ 1.5 s（远低于 3 s）。代价是回溯位图约 `n·2^h/4 ≈ 77 MB`（`h = 8`），800k 时约 51 MB。
  - 64 KiB 档位差异最明显：800k 只能取 `u = 1`（+25.3% 体积），1.2M 可取 `u = 2`（+9.8%，PSNR 高 3.2 dB）。
- **极化折价 A/B（`polarize_weight = 0.65`）**：4 KiB / h=8 / 1.2M 下 `7,870` 次改动、`57.51 dB`，与关闭时 `7,872 / 57.55 dB` **无可测差异**。按"净收益为正才转正"的规则，默认保持 `1.0`。

## 二、体积增幅与推荐档位

| 载荷 | bpp（对 2.42 M 系数） | 体积增幅 | 相对推荐档位 |
| ---: | ---: | ---: | --- |
| 4 KiB | 0.014 | +0.05% | 远低于上限 |
| 16 KiB | 0.054 | +0.70% | 低于上限（0.10） |
| 64 KiB | 0.217 | +9.84% | **2.2 倍上限** |

计划中"体积增幅 ≤ +8%"的验收线在 4 KiB/16 KiB 档位轻松通过；64 KiB 档位超出（约 +10%），原因是该档位已把约 10% 的 AC 系数全部改动，熵编码变长是三元 LSB 型编码的固有代价（旧 V2 在同等载荷下靠 `|c| ≥ 2` 门槛回避零系数，但代价是 71% 的槽位不可用、极端载荷直接无解）。

处置：

1. **推荐档位内（≤ 0.10 bpp）增幅 < 1%**，这是工具的默认工作点；
2. `--enforce-safety` 可硬性拒绝超出档位的载荷；
3. 文档（README / WIRE_SPEC）明确写出 64 KiB 档位的实测增幅，不做粉饰。

## 三、可检测性：标定检测器再校准

三元码把大量改动落在 `0 ↔ ±1` 上，而原 F5 配对统计从 `|c| = 2` 起算，对这部分改动是盲的——实测满容量载体在旧统计下只报到 0.068（低于 0.09 阈值）。统计量改为**包含 `(0, 1)` 配对**后重测 80 图语料（不可压缩载荷）：

| 人群 | 中位 | p95 | 最大 | 阈值 0.05 下检出 |
| --- | ---: | ---: | ---: | ---: |
| 干净载体 | 0.000 | 0.008 | **0.011** | 0%（误报） |
| 推荐载荷（≤ 0.10 bpp） | 0.000 | 0.000 | 0.007 | 0% |
| 满容量 | 0.141 | 0.656 | 0.741 | **85%** |

- 阈值 `CALIBRATION_FLAG_RATE` 由 0.09 调整为 **0.05**（干净最大值 0.011 的 4.5 倍余量），`CALIBRATION_STRONG_RATE` 保持 0.15。
- 不同阈值的满容量检出率：0.02 → 91%、0.03 → 90%、0.04 → 88%、0.05 → 85%、0.06 → 81%、0.09 → 68%。
- 结论与威胁模型一致：**推荐档位下载荷在统计上不可见，满容量必被看见**；这也是"载荷率是最大变量"的实测印证。

## 四、语料回归

`cargo test --release --test batch_stego -- --ignored`：

- 19 个载体全部通过（15 正常 + 4 优雅拒绝：APNG、调色板 PNG、Adam7、渐进式 JPEG）；
- 满容量自检：**10/15 被标记**（risk ≥ 10），未标记的 5 个是 PNG/低纹理载体（其自检分本就来自载体本身）；
- 兼容性：低载荷（64 B）风险增幅 ≤ 35 的门禁全部通过；
- 过载拒绝：超出容量时报 `Capacity exceeded`（JPEG V3 与空间域措辞统一为大小写不敏感匹配）。

另有一类载体需要单独说明：**Huffman 表过度优化**（表内只有 cover 用到的符号）。这类文件在**稠密载荷**下可能无法编码（`±1` 跨零会改变同块后续系数的 run）。实测：

- 4 KiB 档：`temp/jpeg_huffman/opt` 3 张 + `file-08.jpg` + `sample.jpg` **零失败**；
- 满容量档：合成纹理 `temp/teststego/textures14.jpg` 曾间歇失败（随机盐导致头部比特不同），加入"换盐重试 ≤ 3 次"后 **30/30 成功**；仍不行时返回明确诊断（指出缺失符号并建议用标准表重新保存），绝不写坏文件。
- 表完整（162 符号）的相机照片不触发上述任何路径，逐槽符号检查完全不执行（快速路径）。
