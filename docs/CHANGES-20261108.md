## 2026-11-08 12:22:41 — 容量契约修复：RIFF 4 GiB 余量精确上报 + WebP 静态表标注

来源 `docs/api/spec/CORRECTIONS.md` F 节第 1、2 条。两条都是“探测报得出、写入写不进”的契约缺陷。

- **RIFF `riff_chunk` 容量改为真实余量**：`adapters/riff.rs` 新增 `riff_chunk_headroom()`，按头部声明的 `u32` 大小算出 `u32::MAX - declared - 8`；`strategy_capacities` 把它写进 `capacity_bytes`，余量为 0 时置 `available=false`。此前是 `None`，引擎会填入远大于 RIFF 上限的自身载荷上限，接近 4 GiB 的载体因此被误报可写。普通载体上该值仍大于引擎上限，`apply_engine_payload_limit` 取小值后**报告与写入字节均不变**。
- **`apply_engine_payload_limit` 跳过不可用策略**：`available=false` 的条目不参与上限填充，避免为“不可用”策略报出一个容量数字。
- **WebP 静态表标注适用范围**：`reader=None`（无载体上下文）时 `riff_chunk` 行的 note 改为 “Extended Format (VP8X) only; a Simple Format carrier has no VP8X and falls back to eof”，不再暗示所有 WebP 都支持该策略。带 reader 时的 Simple Format 判断保持原样。
- **测试**：新增 `riff_chunk_capacity_reports_the_u32_headroom`（断言容量恰为 `u32::MAX - declared - 8`）与 `webp_static_capacity_table_marks_the_extended_format_requirement`。
