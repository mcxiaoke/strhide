## 1. 先对齐威胁模型：抗定向检测到底能观测什么

这一节修正了评审文档里一处判断错误，也决定了下表的排序。

| #  | 可观测面                                                                    | 未持密钥能否观测             | 现有防护                                                                                     | 缺口                    |
| :- | :---------------------------------------------------------------------- | :------------------- | :--------------------------------------------------------------------------------------- | :-------------------- |
| 1  | **结构域容器标识**（`prIv`/`stEg`/`SHRD`/`MP4_UUID_NEUTRAL`/APP15/PDF 字典）       | **能**（明文容器树）         | 无                                                                                        | `ContainerTags` ⬅ 高价值 |
| 2  | 结构域信封头 magic（`SHA-256("strhide-standard-header-v2")[..8]`）              | **能**（公开常量，直接 grep）  | `StructureProfile.magic` 已可换                                                             | 已有能力                  |
| 3  | **结构域注入"形状"**（APP15 多段各自接近 65533 上限、新增 chunk 长度、`uuid` box 尺寸、PDF 对象长度） | **能**（长度/段数规律）       | 无                                                                                        | 审计完全未提 ⬅ 高价值          |
| 4  | 内容域头部明文字段（`version=0x40`、`format_id`、裸 CRC32）                           | **不能**               | 槽位集合由密钥化 Fisher–Yates 从**全池**抽取                                                          | 见 1.1                 |
| 5  | **内<u>容域体统计面</u>**<u>（嵌入改动落点、成本图几</u>何）                                 | **能**（统计检测，不需密钥）     | 3 个 PNG 成本模型 + `stc_h/u` + `JpegFormatProfile.grid_rule` + `HevcFormatProfile.stc_*` 已可配 | 成本模型参数化 ⬅ 唯一有效杠杆      |
| 6  | KDF 标签 / AAD 前缀 / PBKDF2 迭代数 / `CURRENT_VERSION`                        | **不能**（永不落盘 / 被掩码包裹） | 无                                                                                        | 仅互不兼容                 |

### 1.1 修正：内容域头部明文与 CRC 掩码对定向检测价值为零

评审文档 §3.3 与 Phase 3-1 曾把「裸 CRC32 + 明文头部」列为高性价比加固项，判定依据是「扫描所有比特偏移找 `CRC32(bytes[0..60]) == bytes[60..64]`」。**该判断错误**，核对如下：

- `png/engine.rs:1205-1209` `header_layout()` → `permute_prefix(&mut slots, header_slots, locate_seed)`；
- `prng.rs:231-234` `fisher_yates_prefix_from()`：`let j = i + rng.gen_range_usize(n - i);`，即第 `i` 位与 `[i, n)` 中任意位置交换 —— **前缀 k 个元素是从整个候选池中抽出的密钥化随机子集**，不是「池的前 k 个」；
- 因此未持密钥既不知道槽位**集合**，也不知道槽位**顺序**，无法把 512 个散落比特重组成 64 字节，CRC 校验无从谈起。

结论：内容域头部的明文性只在**攻击者已持密钥**时才有意义，而此时密文本身已完全暴露。**CRC 掩码、`format_id` 定制、`version` 定制在抗定向检测上的收益为 0**，它们只有「格式互不兼容」价值（而该价值由 S4 的标签/盐更廉价地提供）。

同理，KDF 标签（`payload`/`metadata`/`hdr-stc`/`aad_prefix`/`flac-body-phase`/`hevc-session`/`pe-channel-mask`）**一个都不出现在载体里**：改它们不会让任何检测器的输出变化一个比特。它们的唯一作用，是让「拿着官方二进制 + 已知口令」的人读不出私有载体。

## 2. 逐项成本核算

## 3. 三档打包与总成本

| 档位              | 组合                | 总工时             | 检测收益           | 适用场景                              |
| :-------------- | :---------------- | :-------------- | :------------- | :-------------------------------- |
| **A 集成最小集**     | S1 + S4 + S5 + S6 | **4.5–6.0 人日**  | 容器标识消除         | 第三方集成方，只要求「官方二进制读不出、第三方工具扫不到容器特征」 |

| **C 完整**        | B + S2            | **9.0–13.0 人日** | 容器 + 统计 + 结构形状 | 已知会被做深度结构取证                       |

按「价值 / 成本」排序（抗定向检测口径）：

1. **S1**（2–3 人日，直接消除容器指纹）
2. **S3**（1.5–2 人日，唯一的内容域检测杠杆）
3. **S4**（1–1.5 人日，第三方集成必需，但别指望它降检测率）
4. **S5 + S6**（1.5 人日，让私有构建可自检、可交付）
5. **S2**（3–5 人日，可选，风险最高）
6. 不做清单（见 §2 末）

### Step 0 护栏（0.5 人日）

## 6. 需要现在拍板的两个工程选择

### 选择 1：`ContainerTags` 如何穿到适配器

| 方案           | 做法                                                          | 改动点                     | 工时         | 缺点                                    |
| :----------- | :---------------------------------------------------------- | :---------------------- | :--------- | :------------------------------------ |
| **A 全量改签名**  | 8 个方法全部加 `tags: &ContainerTags` 参数                          | 67 个 impl               | 2.5–3.0 人日 | 7 个不消费 tag 的适配器也要跟着改（纯噪声）             |
| **B 默认方法转发** | 新增 `*_with(&self, tags, …)` 默认方法转发到旧方法，仅 6 个消费适配器覆写；旧方法改为委托 | ≈ 35 处（6 覆写 + 20 调用点改名） | 2.0–2.5 人日 | 过渡期两套入口并存，需在 doc 注释里标清「旧入口仅等价于官方 tag」 |

推荐 **B**：噪音小、默认值语义显式（旧入口 = `ContainerTags::OFFICIAL`），且后续要删旧入口时是纯删除。

### 选择 2：私有成本模型的参数化粒度

| 粒度         | 内容                           | 工时     | 检测收益                |
| :--------- | :--------------------------- | :----- | :------------------ |
| 仅换 3×3 核   | `kernel_id = 1` 指向私有 9 tap 核 | 1.5 人日 | 中（只能骗过对核敏感的一阶检测器）   |
| 核 + 两级低通权重 | 核 + σ1/σ2 级联权重一起私有化          | 2.0 人日 | 中高（整张成本图偏移，模型失配更彻底） |

推荐后者，边际成本 0.5 人日换明显更高的失配度。
