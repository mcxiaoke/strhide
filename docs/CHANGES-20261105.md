## 2026-11-05 15:24:46 — F-24 HEVC embed 单遍双模录制：窗口停止后继续只计数，容量保持精确

- `record_carrier_state_with_capacity`：`TargetSlots` 窗口停止后，用
  `Capture::Count` + `RecordMode::Slots` 从停止 GOP 起把剩余载体计数，只累加
  `CarrierRecord.capacity_band_counts`，不保留槽日志；`PoolProfile::from_record` 优先使用全载体计数。
- embed 仅对非 MP4 使用该路径（MKV/HEIF/AnnexB）；MP4 仍走 20% 采样 probe，容量契约不变。
- 实测 554 MB MKV：1 MiB 载荷 45.75 → 41.41 s（−9.5%）；4 KiB 载荷 24.52 → 24.45 s（−0.3%，窗口仅 63 ms）。
  `capacity` 与 MP4 路径不变；容量值 558,885,126 slots 与 `--exact` 完全一致。
- 峰值内存不升（1 MiB 载荷 6,606 → 6,592 MiB priv）。新增 ignored 回归测试
  `local_hevc_embed_capacity_matches_probe`（MKV+HEIC 断言 embed 容量 == 精确 probe）。

## 2026-11-05 15:23:41 — F-18 结论：结构域 write_core 的 locate 复用判定不做（实测 <5%）

- 逐阶段计时（87 MB PE `ffmpeg.exe` / 405 MB MP4 / 30 MB PNG）显示 locate 只占
  0.9%–5.4%，且默认写入仅 1 次写前 locate；热点是 SHA-256、注入写出与 PE 策略容量扫描。
- 合并写前多次 locate 的相对收益：默认 0%，official+密码 2.7%（仅 PE），
  private+密码最多 5.5%（需给 `HostAdapter::locate` 增加 magic 集合并改全部 adapter）。
  写后自检 locate 是正确性契约，不能裁剪。按“收益 <5% 不增复杂度”原则维持现状。
- 无代码改动。

## 2026-11-05 15:22:15 — F-28 核验：PNG 嵌入路径无重复解码，仅修正过时注释

- 结论：V4 重构后 PNG/JPEG/HEVC 的 embed 分支从同一 CostMap/槽位池返回容量，`stego/io.rs`
  的兜底 probe 只在 `EmbedOutput.capacity == None`（HEIF 缩略图桥）时触发，无需再做解码复用。
- 证据：计数探针显示 `embed`/`capacity`/`extract` 对同一 PNG 各只调用 `decode_png` 1 次；
  4.2 MB PNG：0.12/0.20/0.14 s；30 MB/24.4 MP PNG：2.42/3.15/2.12 s（重复解码应约 4.5 s）。
- 改动：仅修正 `rust/src/stego/options.rs` 中“PNG/JPEG 故意返回 None”的过时注释；无运行时代码变更。
