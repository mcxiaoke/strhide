# CHANGES 2026-11-11
## 2026-11-11 13:55:15 代码审查整改 Batch 3/8：内容域 ISOBMFF box 解析统一（M-4）

MP4 采样表解析、HEIF 属性解析、HEIF 缩略图桥接三处各自实现了 `size32 | tag | largesize` 的 box 头语法（含 `size==0` 与 `size==1` 两个易错分支），现由单一模块提供。

- **新增 `rust/src/stego/hevc/isobmff.rs`**：`read_box_header(bytes, pos, limit, zero)`（严格：整箱必须落在 limit 内）与 `read_box_size_unchecked`（桥接用：只看尺寸字段，由调用方自行做 `size > remaining` 容忍），并显式区分 `ZeroSize::ExtendToLimit` / `Reject` 两种 `size==0` 语义。
- **`rust/src/stego/hevc/mp4_boxes.rs`**：`boxes_in` 与 `top_level_has_moof` 改用共享实现；后者保持"遇到畸形即停止"的容忍语义。
- **`rust/src/stego/hevc/heif_boxes.rs`**：顶层 `meta` 定位、`meta` 子箱、`iinf`/`iref`/`iprp`/`ipco` 五个遍历改为共享实现；容忍/严格语义按原调用点保留（表遍历遇错 `break`，顶层定位与 strict 一致返回 `Err`）。
- **`rust/src/stego/heif/thumb_bridge.rs`**：局部 `read_box_header` 改为委托 `read_box_size_unchecked`，保留调用方原有的截断容错检查。
- **行为边界**：`size==0`、`largesize<16`、64 位尺寸溢出 `usize`、箱体越界四类判定与原来一致；仅畸形输入的 `HevcError` 文案由 `invalid top-level box size` 统一为 `invalid box size`（错误类别不变）。结构域 `structure/adapters/isobmff.rs` 按报告建议保持独立，未跨层共享。
- **验证**：`cargo fmt`、`cargo check --all-features --all-targets`、`cargo clippy --all-targets --all-features -- -D warnings`、`cargo test --all-features --all-targets`、release 构建 + `baseline_hash.py --check`（28/28 全绿，含 MP4/MOV/HEIC/AVIF 全部用例）均通过。
