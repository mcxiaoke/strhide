# 变更摘要 2026-11-05

## 2026-11-05 10:27:07 — P0 批次（修复 F-01/F-02/F-03，commit `49fa875`）

- **F-01 HEVC 写窗口下限**：`hevc_window_target_slots()` 将写入侧 `target_slots` 抬到与读取侧一致的 `HEVC_SUPERBLOCK_POOL_SLOTS(2048)`，修正小载荷 balanced 在多于 2048 槽的多画面载体上写入自洽但永远读不出的问题。新增单测断言写/读 pool 一致，新增 `tests/assets/tiny40.hevc`（40x40 Main profile，约 3 KB）做多画面回归。
  - 影响：仅当载体槽数 > 2048 且写入窗口原本会提前停止时，carrier 的槽选择窗口变大；合法载具的 header 位置语义与读取端统一。`baseline_hash --check` 全绿，无需重建基线。
- **F-02 restore/remove 认证前置与坐标上界**：`remove_core` 改为先经 `open_authenticated_at` 解一次 metadata AEAD，再执行 strip；`validate_against(ube_total_size, host_len)` 增加 `patch_offset+4 <= host_len` 校验；注入区间用已有的 `envelope_coordinates_agree()` 按物理长度（兼容 PNG chunk 位移）校验。`verified_identical` 只有在认证通过后才可能为真。
  - 行为变化：加密信封的 `remove` 现在需要密码（无法解密 metadata 时返回 `Password`），与 fixplan 中“加密信封本来就要密码”一致；明文/非 stealth 信封无需密码。
  - 测试：伪造 `orig_host_sha256`、`patch_offset = u32::MAX-3/u32::MAX/host_len+100`、注入越界与溢出均在 rename 前被拒，载体 SHA-256 不变；正常 restore/remove 行为不变。
- **F-03 跨域占用检测**：新增 `StrHide::ensure_domains_free()`（`facade.rs`，编排层），复用现有 `inspect_any()`；CLI `embed` 与 `write` 在预检阶段探测双域，未带 `--overwrite` 时拒绝，错误信息点名冲突域。`structure`/`stego` 仍互不 import（`import_lint` 通过）。
  - 测试：内容二次嵌入、结构叠加于内容、内容叠加于结构三种情况均被拒且不产生输出；单域往返不受影响。
