# 变更摘要 2026-11-05

## 2026-11-05 11:03:28 — P1 批次（修复 F-04～F-09）

- **F-04 `-o` 覆盖载体**：`core::commit::reject_carrier_output()` 复用 `same_file` 做归一化比较（同文件、相对路径、软链、Windows 大小写）；结构域 `write_payload_to()` 增加载体路径参数并在截断前拒绝，CLI `read` 批量分支与 `extract` 三条输出分支在打开输出前调用同一检查。
  - 测试：`read -i carrier -o ./carrier --overwrite` 与 `extract -o carrier --overwrite` 均被拒，错误点名载体冲突，载体 SHA-256 前后一致，载荷随后仍可提取。
- **F-05 结构域载荷上限**：写入侧在压缩前用读取端同一 `structure_payload_limit(host_len)` 拒绝超限载荷（输入宿主长度是输出宿主的保守上界），消除“写成功、读永久失败”。
  - 测试：64 MiB+1 载荷被拒且无输出；恰好 64 MiB 的边界载荷可写可读（`test_regression`）；`test_security` 的“伪造声明大小”用例改为先写 10 MB 再重封 metadata，保持读侧上限验证。
- **F-06 ISO-BMFF 尾部信封校验**：`trailing_envelope_len()` 改用 `EnvelopeTrailer::unpack()` 校验 magic 与 CRC，`MP4`/`HEIF` 通过 `verify_structure_with_magic` 传入当前 profile/stealth magic；仅靠“offset 0 + 文件长度”的 24 字节伪造尾不再被 L1 当作信封。
  - 测试：`verify_rejects_a_forged_24_byte_trailer_tail`；正常 MP4/HEIF 往返与既有 verify 用例不变。
- **F-07 FLAC `bit_offset` 加宽**：`FlacSlot`/`CompSlot.bit_offset` 与校验偏移表由 `u32` 改为 `u64`，>512 MiB 载体的位偏移不再回绕；公开 API/结构未变（字段均 crate 内私有），无需边界拒绝。
  - 测试：`slot_offsets_keep_bits_above_u32` 用 `u32::MAX+8` 的合成偏移模拟 >512 MiB 载体（注释说明为何无需真实大文件）。
- **F-08 PNG capacity 与 embed 同源**：新增 `body_payload_fits()`（镜像 embed 的 codec/`u` 解析与 `slots_for_codec`）与 `max_raw_payload_for_pools()` 二分，`build_png_capacity_with_pools()` 不再用假设 `u=1` 的闭式反推。
  - 测试：`probe_capacity_is_reachable_by_embed` 改为不可压缩噪声载荷，断言 `capacity` 可嵌入并读回、`capacity+1` 必失败（三个口令）。
- **F-09 PNG `sigma` 校验**：`PngParams::validate()` 拒绝 NaN/±Inf/负数及 `0.1..=10.0` 之外的值，并具名报 `'sigma'`。
  - 测试：`1e300`/NaN/负值/0.05/11 均被拒；0.1、1.0、10.0 可写可读。
- **测试/验证**：`cargo fmt --all --check`、clippy `-D warnings`、release build、lib 522（1 ignored）、doc 8、lifecycle 144、regression 114、security 25、media 14、pe 41、cli 139、local 18（14.32s）、heavy 5（73.27s）、`import_lint` 通过、`baseline_hash --check` 28/28 一致。

## 2026-11-05 10:27:07 — P0 批次（修复 F-01/F-02/F-03，commit `49fa875`）
