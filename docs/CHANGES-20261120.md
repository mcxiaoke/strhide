# CHANGES 2026-11-20

## 2026-11-20 10:39:20 fix(structure): resolve HEIF strip panic, PDF/JAR signature check, APK bypass, ZIP EOF verify, and PE geometry bounds

1. **HEIF 切片越界 Panic 修复（`src/structure/adapters/isobmff/heif.rs`）**
   - 在 `heif_item_hidden_strip` 截断前补充 `iloc_buf.len() < header_len + iloc_item_len` 校验，杜绝畸形输入下切片收缩导致写回 `iloc_buf[14..18]` 时越界崩溃。

2. **数字签名检测与 APK 伪装加固（`src/structure/rejection.rs`）**
   - PDF 跨窗口签名识别：`check_pdf_signature` 将 `/ByteRange`、`/Sig` 及 RFC 3161 `/DocTimeStamp` 改为全文件状态累加，不再受限于单个 64 KiB 窗口，避免 LTV 完整证书链 PDF 被漏检修改。
   - JAR 签名补齐与防 OOM：`check_jar_signature` 增加 JDK 7+ 标准 ECDSA `.EC` 签名文件检测，并为 `cd_size` 设置 64 MiB 上限，防止伪造数 GB CD 大小触发预检 OOM。
   - APK 伪装绕过拦截：在 ZIP 中央目录前探测 `"APK Sig Block 42"` 签名块，彻底杜绝将 `.apk` 改名为 `.zip` 绕过 Android 签名防护的风险。

3. **ZIP EOF 策略自检修复（`src/structure/adapters/zip.rs`）**
   - `ZipAdapter` 实现 `verify_structure_with_magic`：当常规尾部扫描找不到 EOCD 时，通过 Trailer 识别 >64 KiB 的 EOF 追加信封，并在原容器范围内完成 EOCD 定位，使大 EOF 载荷顺利通过 Level 1 结构验证。

4. **PE 几何与 Seek 溢出防范（`src/structure/adapters/pe/layout.rs`、`src/structure/adapters/mod.rs`）**
   - `pe_geometry` 全面采用 `checked_add`/`checked_mul`，杜绝 32 位架构下畸形 `e_lfanew` 回绕越界。
   - `SegmentedSubStream::seek` 改用 `i128` 范围计算，消除 `u64 as i64` 导致的负数误拒与算术溢出。

## 2026-11-20 10:30:45 fix(core): resolve concurrency lock races, PID overflow, stream compression, and dev-dependency gate

1. **并发锁与 PID 溢出修复（`src/core/commit.rs`）**
   - 修复非 Linux Unix 存活探测：在 `process_is_alive` 中加入 `i32::try_from(pid)` 检查并拒绝 `<= 0`，避免 `u32::MAX as i32 == -1` 时调用 `kill(-1, 0)` 探测全部进程并永真导致的 macOS/BSD 锁无法回收问题。
   - 修复 `TargetLock` 的 TOCTOU 竞态：在 `reclaim_if_stale` 的 `rename` 之后校验隔离锁文件中的 PID 是否与先前观察到的陈旧 PID 一致；若不一致说明并发写者已抢先建立新活跃锁，立即撤回重命名并安全中止回收，防止并发冲撞破坏同一载体。

2. **流式压缩与异常透传（`src/core/compress.rs`、`src/core/crypto.rs`）**
   - 将 `compress_stream` 改为真流式实现：封装 `CountingWriter` 直连 `DeflateEncoder`，随写随流向 `writer`，避免大载荷全量保存在内存堆 `Vec` 中引发 OOM。
   - 修复 I/O 取消异常被吞没：在 `decompress_stream` 与 `decrypt_stream_from_chunks` 中仅将 `UnexpectedEof` / `InvalidData` 映射为 `CorruptedData`，普通 `io::Error` 完整透传，确保 `map_io_cancel` 能正常捕获协作式取消。
   - 加固 Nonce 索引安全：在 `make_chunk_nonce` 中加入 `chunk_index < 0xFFFF_FFFF` 上界防御，防止与元数据 Nonce 碰撞。

3. **依赖与门控修复（`Cargo.toml`、`src/core/mod.rs`、`src/lib.rs`）**
   - 在 `rust/Cargo.toml` 的 `[dev-dependencies]` 中加入 `serde_json = "1.0.154"`，修复 `--no-default-features` 下 `errors.rs` 单元测试编译失败的问题。
   - 统一 `core-io` 模块条件编译门控，单独启用 `core-io` 时正确暴露 `commit` 模块。
