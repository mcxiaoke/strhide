# 变更摘要 2025-11-04（实际执行日 2026-11-04）

## 2026-11-04 10:42:11 — P0-2

- **PNG 双域复合（IDAT 重压缩位移）**：新增 `Adapter::locate_with_hint` 默认方法，PNG 用本次定位方言的 header 魔数（官方/stealth/私有自定义）识别被重压缩移位的 `prIv` chunk；默认实现保持旧签名调用。
- **L2 坐标校验**：`envelope_coordinates_agree` 新增策略参数，仅对 `chunk` 策略接受“头部写入时坐标 + 实际定位位移”，其余策略仍严格拒绝；移除 `verify_core` 中已失效的 `trailer.ube_offset == ube_offset` 调试断言（位移时故意不等）。
- **strip 坐标重算**：`remove_core` 用 `strip_coordinates_for_location` 依据实际 `ube_offset` 平移 `inject_offset`，非 `chunk` 策略坐标不一致直接报错；避免剥离错位字节。
- **测试**：新增 `png_chunk_envelope_survives_content_recompression_in_all_dialects`，覆盖官方/stealth/私有三方言的读、L1、L2、还原（内容域改写宿主导致原始哈希失配时断言 `RestoreMismatch`；改写头部记录的原始宿主哈希后验证 strip 使用实际定位坐标成功还原）；原 `verify_rejects_a_header_whose_coordinates_disagree` 改用不可位移的 `eof` 策略保持严格拒绝语义。
- 验证：fmt/clippy/build、lib 与全部测试二进制、ignored local/heavy（含 heavy_dual_domain_coexistence_matrix）、import_lint、baseline_hash 全绿；GUI clippy 通过。

## 2026-11-04 10:29:22 — P0-1

- **写路径前置结构校验**：`write_core` 在检测到适配器后、任何注入前调用 `verify_structure`，畸形宿主直接以 `CorruptedData` 拒绝，不再由弱嗅探 + `auto` 的 `eof` 回退静默改写非载体文件；被拒绝时不产生输出。
- **ISO-BMFF 显式尺寸约束**：`isobmff_verify_structure` 记录显式尺寸 box 数量，全为 `size == 0`（延伸到 EOF）的文件视为非容器并拒绝；`ftyp` 校验保留。
- **JPEG SOS 不可达**：`auto` 探测仍返回 `eof`，但写路径的结构校验会先拒绝，实际写入行为从“追加”变为“报错”。
- **测试调整**：新增假 JPEG 与 `[size=0][ftyp]` 两个写拒绝回归用例；原先断言“畸形 WAV/JPEG 回退 eof 并成功写入/还原”的两个用例改为断言写拒绝，`auto` 探测断言保留。
- 验证：fmt/clippy/build、lib 与全部测试二进制、ignored local/heavy、import_lint、baseline_hash 全绿。

## 2026-11-04 10:16:00 — P0-3 / P0-4

- **P0-3 GUI `smart_extract` 文件名清洗**：提取结果的记录文件名统一经 `sanitize_filename` 归一为裸文件名后再 `dest.join`，绝对路径、`..`、分隔符、盘符与 Windows 保留名不再能逃逸输出目录；新增单元测试覆盖穿越样例。

- 验证：rust fmt/clippy/build、lib 与全部测试二进制、ignored local/heavy、import_lint、baseline_hash 全绿；GUI `pnpm build`、clippy、unit/cross/e2e 全绿。
