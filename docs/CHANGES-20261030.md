### 2026-10-30 10:17:02 - 精简 CLI 二进制命令名称为极短命名（sth / sthc / sths / sthv）

- **背景**：此前域专用入口 `strhide-struct` / `strhide-stego` / `strhide-diag` 存在命令过长、前缀累赘及与 `struct` 关键字混淆的问题；敲击命令反而比全量命令多 4~7 个字符。现将 CLI 输出的 4 个二进制命名全面精简为极短命令，降低终端敲击成本与肌肉记忆负担。
- **改动**：
  1. `rust/Cargo.toml` 与 `rust/src/bin/`：
     - 全量主入口：`strhide` -> `sth`
     - 容器结构域（write/read/restore）：`strhide-struct` -> `sthc`（源码文件 `src/bin/sthc.rs`）
     - 内容隐写域（embed/extract/capacity）：`strhide-stego` -> `sths`（源码文件 `src/bin/sths.rs`）
     - 诊断验证域（inspect/verify/scan/list）：`strhide-diag` -> `sthv`（源码文件 `src/bin/sthv.rs`，避免 `d` 代表 daemon）
  2. `rust/src/cli/mod.rs` & `rust/src/cli/args.rs` & `rust/src/cli_i18n.rs`：同步各 Entry point 的 clap 程序名、Usage 格式、banner 以及根选项多语言匹配。
  3. `rust/tests/common/mod.rs` & `rust/tests/test_cli/domains.rs` & `rust/tests/test_cli/config.rs`：更新环境变量定位与 CLI 断言，125 项集成测试全绿。
  4. `scripts/release.py` & 文档（`README.md` / `README.zh.md` / `rust/README.md`）：同步发布打包二进制清单与使用说明。
- **验证**：

### 2026-10-30 09:37:03 - 修复 GUI 编译失败：WriteOptions 缺少 overwrite 字段

  （`gui/src-tauri/src/commands/structure.rs:65`）。

  `WriteOptions` 时漏传。GUI 的 Cargo.lock 之前锁 `strhide 0.7.4`，本次 lib 升到 0.8.1
  触发重新编译后暴露——属既有 GUI/lib 不同步问题，不是域入口改动引入。
- **改动**：`gui/src-tauri/src/commands/structure.rs` 的 `WriteOptions` 字面量补
  `overwrite`（与前置检查同一个 `req.overwrite` 值），保证 IPC 层与引擎层覆盖策略一致。
  其余 Options（Read/Restore/Embed/Extract/SmartExtract）已逐项核对，字段完整。

### 2026-10-30 00:14:30 - 新增 3 个域专用 CLI 入口（单 package 多 bin，共享 lib）

> 本批工作自 2026-10-29 23:29 起，方案与评估见 `docs/multi-exe-cli-plan_20261029.md`。
> 全量 `strhide` 入口保留；域划分 3 个（struct/stego/diag）；未做 feature 裁剪、未改 workspace、未改 LTO。

- **背景**：单 exe 的 10 个子命令分 3 域，`--help` 混杂、工具名无语义；拆多 exe 更清晰。
  为不复制整套 CLI 逻辑（pwgen `pwr` 的教训），采用 Cargo 一个 package 多个 `[[bin]]`，
  全部链接同一 `strhide` lib crate。
- **改动**：
  1. `rust/Cargo.toml` + `rust/src/bin/`：新增 `strhide-struct` / `strhide-stego` /
     `strhide-diag` 三个 `[[bin]]`（`required-features=["cli"]`）与三个 ~9 行薄 main，调用
     `cli::run_domain_cli(Domain::X, argv)`；全量 `strhide` 不变。
  2. `rust/src/cli/args.rs`：抽 `GlobalArgs` 共享 `-c/-q/--lang`；拆出
     `ContainerCommands` / `StegoCommands` / `DiagCommands`（复用现有 10 个 Args struct，
     仅重复变体声明）+ `StructCli` / `StegoCli` / `DiagCli` 三个 Parser + 3 个
     `From<域enum> for Commands` 归一化实现。
  3. `rust/src/cli/mod.rs`：新增 `Domain`（name / command / banner）；`run_cli_with` 转发
     `run_domain_cli_with(engine, domain, argv)`，预解析 / 配置 / 语言 / 横幅 / 错误 / help
     全部按域复用；域解析结果归一化为全量 `Commands + quiet`，**10 个分派分支与
     `cmd_structure` / `cmd_stego` / `cmd_diag` 三个 handler 文件一行未改**。
  4. `rust/src/cli_i18n.rs`：根 about 与根选项 help 加 3 个域根别名，中英文 help 同样生效。
  5. `rust/tests/test_cli/domains.rs`（挂到 `tests/test_cli.rs`）：新增 5 例——本域 help
     只列本域命令、跨域子命令被拒、`--version` 用各自名字、`--lang zh` / `-q` 共享选项生效、
     `list --json` 与全量入口字节一致。
  6. `scripts/release.py`：`CLI_EXE_STEMS` / `cli_bins()`，`build_cli` / `clean_build` /
     `package_cli` 改为处理 4 个 exe（`cargo build --release --features cli` 命令不变，Cargo
     自动产出所有满足 required-features 的 bin）；`README.md` / `README.zh.md` /
     `rust/README.md` 补域入口说明。
  7. `.gitignore`：加 `!rust/src/bin/` 例外——原 `**/bin/` 会忽略新 bin 源码，导致 CI 构建失败。
