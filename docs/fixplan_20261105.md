### 4.2 性能与内存（13 条）

#### F-35 [P3] CLI `write -d <大文件>` 把载荷缓冲两份（峰值约 2×）

- **来源**：A `P2-09`。
- **证据**：`rust/src/cli/cmd_structure.rs:180-200`：先 `fs::read` 载荷，再传 `Payload::bytes`，构建 plaintext 时又克隆。
- **修法**：用 `Payload::file`/借用读取，避免 `Vec` 复制；或让 `build_plaintext` 接受 `&[u8]`。**成本** S。**风险** 无 wire。**验收**：大 `-d` 峰值下降；文本/文件载荷 roundtrip 一致。
- **结论（已修复，本批）**：`into_buffered` 对 `Bytes`/`Buffered` 返回 `Cow::Borrowed`，写入路径不再整份 `to_vec()`。64 MiB 单载体写入峰值 134.1→70.1 MiB（−47.7%），耗时 163→142 ms；输出大小与读回 SHA 一致，baseline 28/28。

#### F-36 [P3] `verify` 对 stealth 载体做 3 次全量结构校验

- **来源**：C `XH-12`。
- **证据**：`rust/src/structure/engine.rs` verify 路径重复调用 locate/read；C 报告实测 3 次。
- **修法**：一次 locate 结果缓存给 verify/read 共用。**成本** S/M。**风险** 无。**验收**：stealth verify 耗时下降，结果不变。
- **结论（不做）**：实现「locate 命中 stealth 时 L1 先试 stealth magic」并实测：83 MB stealth PNG `verify` 2179→2189 ms，`inspect` 单独 2019 ms；三次 L1 扫描合计约 160 ms，跳过两次收益 <5%（噪声内），且引入方言优先/回落分支。按收益不足承担改动风险回退，未保留 `used_stealth` 改动。

#### F-37 [P3] `read` 把解密结果与解压结果同时留在内存（2× 峰值）

- **来源**：C `XH-13`。
- **证据**：来源报告指出 `read` 路径在解压完成前仍持有解密缓冲。
- **修法**：解压后显式 `drop(encrypted)`；或让解压写入同一 `Vec`（`Vec::clear` 后复用）。**成本** S。**风险** 无。**验收**：大载荷 read 峰值下降。
- **结论（不做）**：实测「解压后 drop」前后峰值 100.8→100.7 MiB（无变化），耗时 194→203 ms；峰值发生在 `decompress_stream` 执行期间，事后释放无法降低。真正消除 2× 需流式 decrypt→inflate，超出最小实现；已回退该行，两次输出 SHA-256 一致。

#### F-38 [P3] ZIP EOCD 扫描最坏 O(n²) 次 `memcmp`

- **来源**：C `XH-15`。
- **证据**：`rust/src/structure/adapters/zip.rs:45-75`：每个 EOCD 候选都回扫中央目录。
- **修法**：单次从尾部向前找最新 EOCD，再单次解析 CD；限制候选数量。**成本** S。**风险** 需兼容注释含 EOCD 的 ZIP。**验收**：大注释 ZIP 定位耗时下降；正常 ZIP 正确。
- **结论（已修复，本批）**：单次扫描得到降序候选 `Vec`，双 pass 复用；66,140 B 高密度 EOCD 注释样本 `inspect` 38→29 ms（最终复测 38→34 ms，启动约 25 ms），扫描本身约 13→4 ms；JSON 输出与改前一致，候选顺序/decoy 防护未变。

#### F-39 [P3] ZIP 写前 JAR 签名检查整段缓冲 Central Directory

#### F-40 [P3] HEVC 容量 probe 的“20% 采样”是前缀采样，且两端被 clamp 破坏比例

#### F-42 [P3] FLAC 容量报告比 embed 实际少算 `8 × ext_len` slots
