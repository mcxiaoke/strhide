## 0. 结论

1. **`0.05` 这个阈值在 PNG 上不可用**：216 个真实素材载体里，RS 25%、SPA 31%、WS 34% 越界。这不是"轻微误报"，而是把四分之一到三分之一的正常图片判成可疑。
2. **分层采样（B2）必须做，但它让数值整体上移**：旧逻辑只看 `pixels[..4_000_000]` 再截断 512 行，竖图（`wallhaven` 3106×4774）实际只统计顶部 6.7%——风景图那一条带是天空。改看顶/中/底三段后同一阈值下越界数从 23/27/28 升到 29/32/35（`temp` 语料口径），因为原来的采样低估了纹理。
3. **这三个估计器对"LSB 替换"依然有效**：226 个真实载体的 LSB 全替换版本，中位数 ws 1.000 / rs 0.958 / spa 0.999。因此阈值不是"关掉检测器"，而是调到它真正建模的那类修改上：`0.70` 时 216 个真实载体只有 1 个 ws 越界（rs/spa 各 0），替换样本仍有 100%/85%/100% 被检出。
4. **对本项目的三元 `±1` 匹配基本无响应**：64 B 与 4 KiB 载荷下检测值与载体**逐位相同**；满载（RGB，约 0.9 bpp）时 29 个载体里 27 个数值**下降**、2 个不变、0 个上升。29/29 全部 `0/clean`。这是替换模型检测器的固有盲区，已被实测确认。
5. **`0.70` 只在 ≥50% 替换率上可靠**：30% 替换率下 ws/spa 中位数 0.373/0.315，`0.70` 一次都不触发（41/41 判 clean）。要覆盖低替换率就必须把阈值降到 0.40 左右，代价是 3% 左右的误报——本轮选择保误报，把限界写进代码注释。
6. **独立套件（Aletheia SRNet/EffNet）不能直接当判据**，且**PNG 与 JPEG 用的是两套不同模型**（见 §4）；干净载体上 EffNet-HILL 给 0.48~0.9975，跨语料偏差比嵌入信号大一个数量级。

## 2. B2：分层采样

**改动**（`rust/src/analysis.rs`）：

- 新增 `spatial_slabs()`：按 stride 取顶 / 中 / 底三段**连续行**，每段最多 512 行、4 MB；总行数不足三段时整图分析（小图行为与旧版一致）。
- `track_spatial_domain` 对每个 slab 分别跑 WS/RS/SPA，**按段求平均**（不是取最大：载荷铺满整图，取最大会让一条异常带主导结论）；chi2 改为**汇总直方图**后一次计算，与单趟全图统计等价。
- 之所以不做"把行拼成一个 buffer"：三个检测器都假设垂直相邻（3×3 窗口 / 上下采样对），拼接会凭空造出从未存在的邻居对；分段各自统计是精确的。

**效果**（`temp` 语料 107 个干净载体，阈值仍为 0.05）：

| 检测器 | 旧（顶部 512 行）p50 / p90 / max / 越界 | 新（三段平均）p50 / p90 / max / 越界 |
| :--- | :--- | :--- |
| WS | 0.017 / 0.202 / 0.933 / 28 | 0.022 / 0.235 / 0.758 / **35** |
| RS | 0.012 / 0.115 / 0.621 / 23 | 0.021 / 0.193 / 0.614 / **29** |
| SPA | 0.019 / 0.156 / 0.784 / 27 | 0.023 / 0.225 / 0.758 / **32** |

单张 1920×1280 的扫描耗时不变（0.354 s → 0.354 s；PNG 解码与 deflate 占大头，统计不是瓶颈）。

## 3. B3：阈值标定（真实语料）

### 3.1 干净载体分布

216 个真实 PNG 载体（阈值 0.05 时的越界数放在最后一列）：

| 检测器 | p50 | p90 | p99 | max | >0.05 | >0.70 |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: |
| WS | 0.018 | 0.221 | 0.433 | 0.729 | 73/216（34%） | 1 |
| RS | 0.016 | 0.127 | 0.295 | 0.420 | 53/216（25%） | 0 |
| SPA | 0.022 | 0.188 | 0.357 | 0.549 | 67/216（31%） | 0 |

最高分是 `DIV2K/0471.png`（ws 0.729、spa 0.549、rs 0.286）：只有 ws 越界，按 Info 计 2 分，仍是 `clean`。

### 3.2 干净载体 vs LSB 替换载体

| 检测器 | 干净 p50 / p90 | 100% 替换 p10 / p50 / p90 | 30% 替换 p10 / p50 / p90 |
| :--- | :--- | :--- | :--- |
| WS | 0.018 / 0.221 | 0.997 / **1.000** / 1.000 | 0.310 / 0.373 / 0.514 |
| RS | 0.016 / 0.127 | 0.000 / **0.958** / 1.000 | 0.177 / 0.260 / 0.329 |
| SPA | 0.022 / 0.188 | 0.964 / **0.999** / 1.000 | 0.302 / 0.315 / 0.408 |

阈值扫描（FP = 216 个真实载体越界数；TP = 226 个全替换样本检出率）：

| 阈值 | WS FP / TP | RS FP / TP | SPA FP / TP | 30% 替换被检出 |
| ---: | :--- | :--- | :--- | :--- |
| 0.30 | 13 / 100% | 2 / 85% | 5 / 100% | 大部分（ws p50 0.373） |
| 0.40 | 5 / 100% | 1 / 85% | 2 / 100% | ws 15/41、spa 5/41、rs 2/41 |
| 0.50 | 1 / 100% | 0 / 85% | 1 / 100% | 极少 |
| **0.70** | **1 / 100%** | **0 / 85%** | **0 / 100%** | **0/41** |
| 0.80 | 0 / 100% | 0 / 85% | 0 / 100% | 0/41 |

选 `0.70`：真实语料上 1/216（0.5%）误报，替换类检出几乎不损失（降到 0.50 也只是把 TP 从 100% 提到 100%，FP 却翻倍）。**代价**是低替换率看不到——30% 替换时估计值落在 0.26~0.37，`0.70` 一次都不触发；要覆盖它得降到 0.40，误报约 3%。这个取舍写在 `SPATIAL_RATE_THRESHOLD` 的注释里。

**最终风险分布（216 个真实载体，阈值 0.70）**：

```
risk 0 / clean          215
risk 2 / clean            1   (DIV2K/0471.png，只有 ws 越界)
```

`suspicious` / `likely-hidden`：0 个。改造前同一集合有 53~73 个越界检测（25%~34%）。

### 3.3 本项目 `±1` 匹配的响应（29 个载体配对）

| 载荷 | WS p50 / p90 / max | RS p50 / p90 / max | SPA p50 / p90 / max | 风险 |
| :--- | :--- | :--- | :--- | :--- |
| 载体 | 0.013 / 0.118 / 0.232 | 0.010 / 0.067 / 0.120 | 0.015 / 0.089 / 0.194 | 29/29 clean |
| 64 B | 同上（逐位相同） | 同上 | 同上 | 29/29 clean |
| 4 KiB | 同上（逐位相同） | 同上 | 同上 | 29/29 clean |
| 满载（RGB ~0.9 bpp） | 0.000 / 0.057 / 0.155 | 0.000 / 0.030 / 0.106 | 0.000 / 0.017 / 0.170 | 29/29 clean |

满载相对载体的方向：SPA **下降 27 / 不变 2 / 上升 0**。三元匹配把差值统计往"更少嵌入"的方向推，替换模型估计器读不出载荷——这与 `batch_stego` 里"满载只 1~2 个载体被载荷推到报警"的结论一致。

## 4. 独立套件交叉核对（`scripts/stego_eval`）

### 4.1 格式 → 模型（已按代码与实跑确认）

| 载体 | 使用模型 | 说明 |
| :--- | :--- | :--- |
| PNG | `SRNet-HILL`、`SRNet-SUNIW`、`EffNet-HILL` | 空域（像素）模型，与本项目 PNG 引擎的 HILL 对应 |
| JPEG | `EffNet-JUNIW`、`EffNet-JMiPOD`、`EffNet-Steghide`、`EffNet-nsF5` | 频域模型，训练目标是 J-UNIWARD / JMiPOD / steghide / nsF5 |

- 代码依据：`core/model_suite.py` 的 `is_jpeg()` + `models = self.jpeg_models if is_jpg else self.png_models`；批量路径也按格式拆分成两组推理。
- 实跑确认（同一编号的两种格式）：`0001.png → [SRNet-HILL, SRNet-SUNIW, EffNet-HILL]`，`0001.jpg → [EffNet-JUNIW, EffNet-JMiPOD, EffNet-Steghide, EffNet-nsF5]`。
- **本项目 JPEG 引擎用的是 UERD，而这个套件里没有 UERD 模型**（JUNIW/JMiPOD/steghide/nsF5 都是别的算法），所以 JPEG 侧的 NN 分数只能算"邻域参考"，不能当 UERD 的检出率。PNG 侧则对得上（HILL↔HILL）。
- 关于"HILL 是不是 JPEG 的"：在这套模型里 HILL 是**空域/PNG** 侧；Aletheia 官方模型包里另有 `effnetb0-A-alaska2-hill.h5`（ALASKA2 是 JPEG 数据集），所以"HILL 也出现在 JPEG 模型名里"是存在的，但本套件加载的三个 PNG 模型都不是那个。

### 4.2 分数表现（6 个载体 × 4 个变体）

| 文件 | 变体 | 综合分 | EffNet-HILL | SRNet-HILL | SRNet-SUNIW |
| :--- | :--- | ---: | ---: | ---: | ---: |
| 0001 | 载体 / 64 B / 4 KiB / 满载 | 21.9 / 21.9 / 21.9 / 23.1 | 0.593 / 0.593 / 0.593 / 0.641 | 0.335 / 0.338 / 0.342 / 0.467 | 0.447 / 0.447 / 0.448 / 0.383 |
| 0003 | 同上 | 22.9 / 22.9 / 22.9 / **55.0** | 0.998 / 0.998 / 0.998 / 0.995 | 0.387 / 0.399 / 0.327 / **0.731** | 0.453 / 0.459 / 0.371 / 0.719 |
| 0004 | 同上 | 23.8 / 23.8 / 23.8 / **55.0** | 0.993 / 0.993 / 0.992 / 0.988 | 0.715 / 0.715 / 0.719 / 0.730 | 0.678 / 0.676 / 0.678 / 0.731 |
| 0006 | 同上 | 75.0 全程 | 0.586~0.605 | 0.401 / 0.401 / 0.406 / 0.328 | 0.576 / 0.576 / 0.574 / 0.361 |

- **绝对分数不可用作判据**：干净载体上 EffNet-HILL 从 0.48 到 0.9975（6 张），SRNet-HILL 0.31 到 0.72。
- **配对比较有信息**：满载时 `0003` 的 SRNet-HILL 从 0.387 升到 0.731；`0003`/`0004` 的经典层综合分从 ~23 升到 55。
- `0006.png`（`temp` 语料）在所有层级都被判高：它本身就是会让估计器发散的图，不是本项目的误报。

> 说明：`scripts/stego_eval/README.md` 仍写着 `temp/stego_eval` 路径，实际在 `scripts/stego_eval`；本次只用其 CLI/API，未改动它。

## 6. 验收

- 真实载体 216：215 个 `0/clean`、1 个 `2/clean`，**无 suspicious / likely-hidden**；改造前同一集合 25%~34% 的检测越界。
- LSB 全替换 226：`risk >= 50` 187/226（83%）；检出率 ws/rs/spa = 100%/85%/100%。
- 本项目 embedding 87 个变体：全部 `clean`，与载体的检测值在低/中载荷下逐位相同。
- `cargo test` 全绿、`cargo fmt --check` 通过、`cargo clippy --all-targets -D warnings` 无警告；`batch_corpus` 240/240；`batch_stego` 22/22（3~4/18 命中，载荷驱动 1~2）。

## 7. 局限与后续

1. **低替换率盲区**：`0.70` 覆盖不到 30% 替换率。若需要，改成两档（`Info` 在 0.40、`Suspicious` 在 0.70）比单阈值更合适，但要先有更多真实语料确认 0.40 的误报率。
2. **估计器发散样本**：`temp` 语料里 `0006.png` 会让 ws/spa 饱和到 0.75。真实语料里只出现 1 个（0.729）。是否在"两路同时饱和但 rs 很低"时标注"估计器不可靠"，需要更多样本。
3. **缺一个匹配类检测器**：要把"我们的嵌入是否可见"变成可测量结论，需要建模 LSB matching 的统计量或有标定的 CNN；现有 NN 模型必须先在目标语料上重标定阈值（干净图跨度 0.48~1.00）。
4. **JPEG 侧没有对应模型**：套件里没有 UERD 模型，JPEG 的 NN 交叉核对只能算邻域参考。
5. CLI 仍未在容量输出里标注"载荷槽位含 RGB 三通道"，同 P3 遗留项。
