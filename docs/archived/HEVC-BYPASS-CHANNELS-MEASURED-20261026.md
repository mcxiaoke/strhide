## 0. 结论摘要

1. **今天已吃掉最肥且最安全的一块**：`coeff_sign_flag`。在 4K 78 帧片段上，全部 CABAC 二值化事件 4,174 万，其中旁路位 1,056 万；当前槽池 362 万（引擎去 DC / EPB 后 278 万），即**旁路位的 26%、全部 bin 的 6.7%**。
2. **指南"通道 C"（`coeff_abs_level_remaining` 定长旁路后缀 LSB）实测只有 +5%**，远低于指南估算的 +130%。原因：`coeff_abs_level_remaining` 仅在 `base == threshold`（系数大到需要逃逸编码）时才出现，且只有在 `c_rice_param >= 1` 时才带定长后缀——真实片段上二者交集极小（24.2 万个后缀 bin / 18.1 万个 LSB，对比 362 万个符号槽）。**不值得做**（会改变槽池 = 改变线格式身份，旧载体全部不可读）。
3. **剩余 670 万个"普通旁路位"里绝大部分不可写**：`coeff_abs_level_remaining` 的 **unary 前缀**（`bypass_ones`）占大头，改它会改变码字长度 → Δ ≠ 0 且后续 CABAC 失步。
4. **真正还有容量的只有 MVD 通道**（`mvd_sign_flag` + `abs_mvd_minus2`），但它带 **MVPO 可检测性风险**（必须做 MVP 最优性守卫，需要解码器暴露 `mvp_cur/mvp_other`）；SAO 与 `rem_intra_luma_pred_mode` 容量都很小。
5. **无需解码即可写的通道（SEI / 尾随填充）是 Δ ≠ 0 路径**，要重写 `stsz`/`stco`/`moov`，是独立里程碑，且隐藏性与结构域 `box_uuid` 同类（弱）。

## 2. 指南 12 个位置 × 当前架构：逐条判决

| 编号 | 位置 | 判决 | 依据 |
| :--- | :--- | :--- | :--- |
| 3.1 | `coeff_sign_flag` | ✅ **已实现**（Scheme C） | 引擎的 observer 录制 + 磁带回放重编码，Δ = 0 |
| 3.2 | `coeff_abs_level_remaining` 后缀 LSB | ⚠️ 技术可行，**实测 +5%，暂不做** | fork 钩子已验证可加（`residual.rs::coeff_remaining` 的 `bypass_bits(rice)` 改为带元数据的 `bypass_level_suffix_bits`）；容量收益不足以抵消"槽池变化 → 线格式身份变化"的代价 |

## 3. 为什么"普通旁路位"里的大多数不能写

`coeff_abs_level_remaining` 的码字 = **unary 前缀（`bypass_ones`）+ 定长后缀（rice 位）**。翻转前缀里的任何一位会改变前缀长度 → 整个码字长度变化 → 后续所有 bin 的字节对齐改变（Δ ≠ 0，且磁带回放与解码器状态错位）。因此：

- 可写：定长后缀的 LSB（长度不变，值 ±1）——实测很少（见 §1）；
- 不可写：前缀（占"普通旁路"的大部分）；
- 其余普通旁路为 MVD、SAO、帧内模式残留位，见 §2。

这也解释了为什么指南的"通道 C ≈ 通道 A 的 1.3 倍"估算与实测差 20 倍：该估算假设每个非零系数都带 rice 后缀，而实际上只有 `base == threshold` 的系数才进入 `coeff_abs_level_remaining`，且 `c_rice_param` 从 0 起随幅值递增。
