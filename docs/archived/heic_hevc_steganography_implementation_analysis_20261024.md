## 2. 结构域方案归纳（纳入 `strhide write` 适配器）

HEIF（ISO/IEC 23008-12）基于 ISOBMFF 树状 Box 结构，规范天然支持多 Item 存储架构。此部分应当作为 `adapters/heif.rs` 的新增策略（Strategies）实现：

### 2.1 候选策略设计
1. **`box_uuid`（当前已支持）**：在文件级追加自定义 `uuid` Box，写入载荷与 UBE 元数据。
2. **`item_hidden`（拟新增，推荐）**：
   - 在 `meta` Box 内的 `iinf`（Item Info）增加一条私有 Item 描述（如 `mime` 设为 `application/octet-stream`）；
   - 在 `iloc`（Item Location）中记录该 Item 对应载荷在 `mdat` 中的偏移与长度；
   - **特性**：主图索引 `pitm`（Primary Item）保持不变。所有的标准看图软件（iOS、Android、macOS、Windows Photos）只会按照 `pitm` 渲染主图，完全忽略未被引用的附加 Item，对主图呈现零干扰，且格式完全合法。
3. **`item_aux`（拟新增，高伪装）**：
   - 模拟 HEIC 的辅助图像机制（`auxl`），将其登记为 Alpha 透明通道、深度图（Depth map）或 HDR 增益图。
4. **`free_atom`（拟新增）**：
   - 将载荷伪装为 ISOBMFF 标准的 `free` 或 `skip` 填充 Box，所有合规播放器与解析器均会自动跳过。

## 3. HEVC 帧内压缩域自适应隐写（方案三深度剖析）

此方案为真正的 `stego` 范畴：直接针对底层 H.265/HEVC 帧内压缩码流或编码语法元素进行率失真驱动的自适应嵌入。

### 3.1 核心理论障碍与应对机制（对照与学术实证）

直接在 HEVC 码流中做隐写面临三大毁灭性缺陷，必须通过特定的算法机制规避：

| 核心痛点 | 物理成因 | 粗暴修改后果 | 压缩域自适应隐写对抗方案 |
| :--- | :--- | :--- | :--- |
| **1. 帧内失真漂移<br>(Intra Drift)** | HEVC 亮度具有 35 种角度预测，相邻块依赖当前块右/下边界重建像素作为预测参考。此外存在 Deblocking 与 SAO 环路滤波 | 1 比特的微调导致后续所有预测块基准偏离，在解码端造成严重块效应与失真级联扩散，破坏盲提取 | **方案 A（编码循环内注入）**：在 RDO 阶段介入，让编码器基于修改后的重构像素继续预测后续块。<br>**方案 B（零漂移系数筛选）**：结合预测方向，仅修改对边界无贡献的高频变换子带（如 QDST 特定位置）。 |
| **2. 四叉树率失真敏感<br>(RD Sensitivity)** | 编码树单元（CTU）递归四叉树分裂（$64\times 64 \to 8\times 8$）高度由率失真优化（RDO）决定 | 人工噪声破坏局部最优平衡，极易被双重压缩检测器与结构梯度网络（GradIPMFormer）检出 | **四叉树结构保持（QT-Preserving）**：仅在分裂与不分裂 RD Cost 差距小于阈值的纹理临界区（$\Delta \text{Cost} < \text{Th}$）介入，保持全局最优性。 |
| **3. CABAC 上下文崩溃与码率膨胀 (BRI)** | HEVC 采用上下文自适应二进制算术编码，Regular Bins 强依赖自适应概率状态机 | 随意翻转语法位导致后续上下文模型失步，或导致文件体积异常暴增（Bit Rate Increase） | **CABAC 旁路位（Bypass Bins）与 SDH**：利用旁路模式等概率（$p \approx 0.5$）无上下文依赖的特性，保持零码率增长（Zero Bitrate Increase, ZBI）。 |

---

### 3.2 四大前沿压缩域自适应隐写算法全景对比

结合学术界与开源最新前沿，四大压缩域方案的技术细节如下：

#### 方案 3.1：SDH 与 CABAC 旁路符号位恒定码率隐写（工程落地首选）
* **载体元素**：变换系数符号位（`coeff_sign_flag`）与原生 Sign Data Hiding（SDH）。
* **原理**：
  HEVC 标准（ITU-T H.265 §7.3.8.11）原生定义了 SDH 机制。在 $4\times 4$ 变换子块内，当首尾非零系数在扫描顺序上的距离大于 4 时，第一个非零系数的符号位不显式写入，而是由该子块所有非零系数绝对值之和的奇偶性（$\sum |c| \pmod 2$）决定。
* **隐写映射**：
  将奇偶校验目标替换为经 STC 编码后的载荷比特。当奇偶性不符时，编码器在子块内挑选率失真代价最小的一个系数进行 $\pm 1$ 调整。
* **优势**：
  1. **零码率膨胀（Zero Bitrate Increase, ZBI）**：CABAC 旁路位不走概率模型，不产生额外比特；
  2. **提取极其轻量**：提取端无需解码整张图像，只需解析语法并求和取模即可盲提取，对终端计算压力极低；
  3. **高容量**：变换系数符号位占整段码流的 $12\% \sim 17\%$。

#### 方案 3.2：IPM 优先级保持与抗漂移自适应隐写
* **载体元素**：亮度块 35 种帧内预测模式（Intra Prediction Modes）。
* **原理**：
  在编码器对 35 种候选模式完成全率失真代价（RD Cost）排序后、**尚未将重构像素写入参考缓存前**介入。当最优模式与次优模式的代价差 $\Delta \text{Cost} < \text{Threshold}$ 时，用次优模式替换最优模式。
* **消除漂移的核心**：
  替换后，编码器**必须正常执行**该模式下的残差变换、量化以及重构像素生成。后续相邻块自然以“已嵌入后的真实像素”作为参考，编码端与解码端预测完全同步，彻底斩断失真漂移。

#### 方案 3.3：TU/CU 四叉树分块结构保持隐写
* **载体元素**：四叉树分裂标志（`split_cu_flag` / `split_transform_flag`）。
* **原理**：
  在 $16\times 16$ 或 $8\times 8$ 边界层级，仅在分裂与不分裂的总 RD 代价高度吻合时介入，强制选择分裂或不分裂。
* **抗检测特性**：
  变换块内残差依然来自真实场景的正规变换量化，且预测模式保持全局最优，完全不包含空域人为加性噪声，对 SRNet / XuNet 等深度学习空域分析器具有天然免疫力。

#### 方案 3.4：$4\times 4$ QDST 零漂移高频系数隐写
* **载体元素**：$4\times 4$ 亮度块量化离散正弦变换（QDST）系数。
* **原理**：
  利用正弦变换（DST-VII）在边界重构上的基函数特性，计算各频域系数对右边界列与下边界行的空间投影矩阵。仅挑选投影加权接近为 0 的高频系数参与 STC 嵌入，使边界重构误差控制在量化容限内。

## 4. Rust 生态现状与工程落地路线评估

### 4.1 Rust 开源生态核查结论
经过对 crates.io 和 GitHub 生态的深入对照核查：
1. **`oxideav-h265`**：
   - **状态**：纯 Rust、零 `unsafe`，遵循 ITU-T H.265 标准开发的模块化框架；
   - **能力**：具备完整的 NALU 单元、参数集（VPS/SPS/PPS）、Slice Header 语法解析以及 CABAC 熵解码引擎；
   - **适配度**：非常适合作为提取端（Extract）和只读语法分析底座。
2. **`rust_h265` / `heic`**：
   - 具备纯 Rust 的 HEVC 帧内解码与 HEIC 容器解析能力，具备 SIMD 加速（AVX2/NEON）。
3. **`scuffle-h265`**：
   - 专注高效解析 SPS/PPS 参数集，轻量稳定。

### 4.2 提取端（Extract）与嵌入端（Embed）的不对称性分析
在 `strhide` 落地 HEVC 隐写时，存在关键的工程复杂度不对称：

* **提取端（`extract`，极度轻量，优先纯 Rust 落地）**：
  - 无论是 SDH 方案（计算 $4\times 4$ 子块 $\sum |c| \pmod 2$），还是 CABAC 旁路位读取，**都不需要运行完整的视频渲染流水线，更不需要率失真优化（RDO）**；
  - 仅需利用 `oxideav-h265` 的 CABAC 语法解析器遍历 TU 块系数，提取出载体比特流，送入 `strhide::stego::coding::stc` 即可完成解码；
  - **结论**：提取端可完全做成纯 Rust、轻量、静态链接，不依赖任何 C++ 动态库。

* **嵌入端（`embed`，涉及率失真决策与码流重写）**：
  - **路径 A（Bitstream 旁路位直接微调，推荐中短期）**：
    若载体已经是现成的 HEIC 文件，且其包含 SDH 冗余或 bypass bins，直接在码流层进行最小代价翻转并重算 slice 算术校验。
  - **路径 B（编码器流水线联合嵌入，推荐长期）**：
    将隐写挂载在 HEVC 编码过程中（例如接入 C++ `x265` / `HM` 或 Rust `oxideav-h265` 编码器），在 RDO 计算时同步由 STC 驱动。

## 5. `strhide` 落地实施规划

### 5.1 第一阶段：容器结构域支持（`write` / `read`）
- **目标**：在 `rust/src/adapters/heif.rs` 中落地合法的 ISOBMFF Item 隐藏；
- **具体工作**：
  1. 扩展 `adapters/isobmff.rs`，实现解析与重写 `iinf`、`iloc` 的辅助函数；
  2. 新增 strategy `"item_hidden"`：将载荷登记为一个不挂载在 `pitm` 上的非视觉 Item，存入 `mdat`；
  3. 保留并增强现有的 `box_uuid` 策略。

### 5.2 第二阶段：自适应隐写域架构接入（`stego`）
- **目标**：扩展 `stego` 模块，新增 `hevc` 子模块；
- **架构对接点**：
  ```
  rust/src/stego/
  ├── mod.rs               ──> embed_carrier / extract_carrier 增加 HEIF/HEIC ftyp 嗅探
  ├── coding/stc.rs        ──> 复用已有 STC V3 格码求解器 (直接复用，零修改)
  ├── prng.rs              ──> 复用基于密钥的置乱序列 (直接复用，零修改)
  ├── envelope.rs          ──> 复用 AES-256-GCM 载荷信封 (直接复用，零修改)
  └── hevc/                ──> [新模块]
      ├── mod.rs           ──> HEVC 隐写入口与参数校验
      ├── bitstream.rs     ──> 基于 oxideav-h265 范式解析 NALU 与 CABAC 语法
      ├── sdh.rs           ──> 4x4 子块非零量化系数奇偶性提取与调制
      └── cost.rs          ──> 系数量化误差与纹理自适应代价模型
  ```

### 5.3 第三阶段：抗检测性基准评测
- 将生成的 Stego HEIC 样本纳入系统的批量测试套件（`tests/batch_stego.rs`）；
- 引入轻量级双重压缩特征检验与 IPM 共现矩阵（IPMC）偏差测试，确保无码率突变（$\text{BRI} \le 0.5\%$）与无漂移伪影。
