# 威胁模型与安全边界 (Threat Model)

> 适用 `strhide` 0.9.x。本文回答一个问题：**这套工具在什么条件下成立，什么条件下一定不成立。**
> 密码学细节以 [api/spec/CRYPTO.md](api/spec/CRYPTO.md) 为准，本文只讲"承诺与失效"。
> 若你只想看结论，直接读 §4 的失效条件表与 §6 的威胁→对策表。

---

## 1. 阅读顺序

| 读者 | 建议 |
| :--- | :--- |
| 使用者 | §3 资产、§4 失效条件、§6 部署建议 |

## 2. 对手模型

我们区分五类对手，**每一类的能力边界都不同，混着谈会得到错误结论**。

| 编号 | 对手 | 能力 | 本工具的目标 |
| :--- | :--- | :--- | :--- |
| **A1** | 静态检查者 | 拿到成品文件，可用 `file`/`binwalk`/格式解析器/`sth scan` 类工具，能看到字节与结构 | 非 stealth 模式下**不隐藏存在性**，只隐藏内容；stealth 模式下不留下可归因到 strhide 的固定特征 |
| **A2** | 统计检测者 | 有 steganalysis 工具与参考语料，能在像素/DCT/码流层做统计判决 | 依靠代价模型（HILL / S-UNIWARD / MiPOD / UERD / J-UNIWARD / J-MiPOD）把改动压到代价最低的位置；**不承诺低检测率，只承诺"不比同类算法更差"** |
| **B** | 有载体无口令者 | 拿到加密载体，可离线暴力破解、可对比多份载体 | 机密性由 KDF 与 AEAD 承担：结构域 PBKDF2 100,000 轮、内容域 200,000 轮；读侧拒绝低于 `max_pbkdf2_iterations`（默认 200,000）的声明，避免降级 |
| **C** | 有口令的第三方 | 知道口令，但不知道私有方言 | 默认情况下**能完整读出**。只有编译期私有方言（[PRIVATE_BUILD.md](PRIVATE_BUILD.md)）能在同口令下隔离，且它只断开归因链，不提高抗统计检测能力 |
| **D** | 本地攻击者 | 同一台机器上的其他进程/用户，能读进程列表、临时目录、`.bak`、崩溃转储、终端历史 | 不承诺防内存取证；但要求：密钥不在 `Copy` 结构里残留、临时文件不残留下半成品、口令不被迫落在命令行 |
| **E** | 供应链攻击者 | 能影响依赖、构建脚本、发布产物 | 无网络代码、无遥测；发布产物带 `SHA256SUMS.txt`；**当前未签名**（见 §5.6） |

不在模型内的对手见 §7。

## 3. 资产

### 3.1 受保护对象

1. **隐藏的明文**（文字或文件内容）。
2. **口令 / 32 字节文件密钥**。
3. **派生密钥**：结构域 `payload_key` / `meta_key` / `header_mask`；内容域 L1 `master`、L2 `locate_seed` / `magic4`、L3 `enc_key` / `perm_seed` / `stc_seed`。
4. **宿主的原始可还原性**：结构域记录原宿主 size 与 SHA-256。
5. **"是否使用了本工具"这一事实**（归因）。
6. **行为元数据**：文件路径、时间戳、日志内容。

### 3.2 密钥层级与信任根

| 域 | 信任根 | 说明 |
| :--- | :--- | :--- |
| 结构域 UBE v2 | 口令 → PBKDF2(100k, 16B salt) → HKDF，分 `payload` / `metadata` 两支；AEAD 固定 AES-256-GCM | stealth 模式的魔数与 76B 头掩码从口令另派生一支，与信封 salt 解耦 |
| 内容域 V4 | 口令 → HKDF（有域时）→ PBKDF2(200k, `pre_salt`) → L1 `master` → L2 定位 → L3 会话 | `pre_salt` 由**嵌入前后不变的载体元数据**构造（PNG 只用关键块，JPEG 用 DC 系数摘要），所以改元数据不会毁掉已写入的载荷 |

两域**不共享**标签、AAD 或默认密钥；任何交叉读取都必须返回"无隐藏数据"。

## 4. 失效条件（这张表就是承诺的边界）

| 承诺 | 成立的条件 | 一定失效的情形 |
| :--- | :--- | :--- |
| 内容机密性 | 使用了口令或 32 字节密钥；口令不在对手手上 | 未设口令 → 回落到公开常量（`PUBLIC_DEFAULT_SECRET` / `BUILTIN_DEFAULT_KEY`），**任何官方构建都能读**；口令是弱口令；口令泄漏在 shell 历史、进程列表、日志、`.bak` |
| 载荷完整性 | AEAD tag 覆盖密文与 AAD | 载体被截断/损坏；两个域互相覆盖导致结构被破坏（`RestoreMismatch.residual_envelope` 会给出诊断） |
| 原宿主可 100% 位精确还原 | **仅结构域**，且写入后载体字节未被改动 | 写入后再做内容域嵌入、任何重编码/重压缩/再存盘；此时 `restore` 报 `RestoreMismatch` 并拒绝输出（fail closed） |
| 内容域载荷存活 | 像素/DCT/码流/PCM 未被重新生成 | 有损重编码、裁剪、缩放、色彩空间转换、转码；提取失败与"口令错误"**不可区分**（设计如此） |
| 存在性隐藏 | 仅 stealth 模式，且对手没有口令 | stealth 只让魔数与头字段变为口令派生值；**字节体积仍会增长**（HEVC 内容域除外，Δ=0），结构域的注入点仍在容器里 |
| 抗统计检测 | 取决于代价模型与载荷率 | 高载荷率、低纹理载体、重复使用同一载体写多次、对比同类原图 |
| 防伪造/防篡改宿主 | —— | 本工具**不**维护宿主可信性。签名文件（PE Authenticode、PDF `ByteRange`、签名 JAR）会被直接拒绝（`Rejection`），因为注入必然破坏签名 |

## 5. 侧信道清单

### 5.1 体积

- 结构域：必然增长（信封 + 112B 头 + 24B 尾 + 分块开销）。
- 内容域：PNG/JPEG/WAV/FLAC 会小幅变化（压缩率改变）；**HEVC 设计为零增长（Δ=0）**，因为只翻转 CABAC bypass 符号位。
- 结论：拿"文件大小异常"做筛查的人，对结构域和非 HEVC 载体是有效的。想减少暴露，优先 HEVC 载体 + 接近原始体积的载荷率。

### 5.2 时间与资源

- 结构域固定 ~20 ms（PBKDF2 主导），与载荷大小弱相关。
- 内容域 0.06–14.6 s，跨引擎差两个数量级。**处理时间不是内容大小的可靠代理**，但长时间占用 CPU 在共享主机上可见。

### 5.3 文件系统

- 原地写入默认生成 `<name>.bak`（`backup = true`）：这是**未加密的原件副本**，忘了删就等于自己交出对照样本。`--no-backup` 可关闭。
- 原子提交使用同目录 `.strhide.<pid>.<r>.tmp`；进程被强杀可能留下残留，下次运行会回收，但残留文件本身是可见痕迹。
- 时间戳：默认保留原 mtime（`preserve_time = true`），这对"看起来没动过"有利；反之若关闭，mtime 变化就是信号。

### 5.4 进程与命令行

- `-p <PWD>` 会出现在进程列表与 shell 历史里。优先 `--password-file` 或 `STRHIDE_PASSWORD`。
- `--password-file` 只读第一行；请自行确保该文件权限正确。

### 5.5 日志与 GUI

- CLI `-v`/`-vv` 把 DEBUG/TRACE 打到 stderr，可能包含路径与参数。
- 桌面端有独立的日志面板（Rust 后端 + 前端合并），记录操作、路径与错误文本；导出日志等于导出操作序列。截图/贴日志前先看一遍。
- 桌面端 CSP 为 `default-src 'self'`，IPC 仅允许 `dialog` 与 `opener` 能力；无文件系统插件、无 shell 插件。

### 5.6 分发与签名

- 二进制**未做代码签名**：Windows 会出现 SmartScreen 提示，macOS 会触发 Gatekeeper 拦截。这本身是"来源未验证"的信号，也是对手可以伪造同名二进制的空间。
- 发布页提供 `SHA256SUMS.txt`，请校验后再运行。
- crates.io 发布走 Trusted Publishing（OIDC），无长期 API token。

## 6. 威胁 → 对策

| 场景 | 最低要求 | 建议 |
| :--- | :--- | :--- |
| 只想不让同事随手看到 | 口令 + 结构域写入 | 关闭备份（`--no-backup`），用 `--password-file` |
| 需要"看不出是 strhide 写的" | 口令 + `--stealth` | 同时用私有方言构建，避免官方二进制可读 |
| 需要抵抗取证分析 | 内容域 + 低载荷率（`safety paranoid`） | 高纹理载体、一次一载体、不做二次嵌入；接受检测率不可能为零 |
| 需要原件可完美恢复 | 结构域 + 原始文件哈希留档 | 写入后**不要**再对同一文件做任何处理 |
| 传输敏感数据 | 口令 + 独立信道传口令 | 不要用 `-p`；不要留 `.bak`；不要分享日志 |

## 7. 明确不承诺的部分

1. **不承诺抗国家级取证或主动攻击者。** 不对抗设备控制、内存取证、键盘记录、强制口令。
2. **不承诺载体重编码后仍可用。** 任何中转平台（社交软件、图床、转码服务）都会毁掉载荷，这是设计前提而非缺陷。
3. **不承诺多载体相关性分析下的不可关联性。** 同一口令 + 同一方言 + 相似载体可能被聚类。
4. **不承诺否认性（deniability）到"存在加密载荷"这一层。** stealth 只抹掉固定特征，不隐藏"文件被动过"。
5. **不承诺 HEVC 的专利状态。** 见 [LEGAL.md](../LEGAL.md) §4。
6. **不承诺审计结论。** 本项目没有第三方密码学审计报告；规范的公开是为了让别人能审，而不是已经审过。

## 8. 自检手段

```bash
# 只读检测：结构 + 统计
sth scan carrier.png --json

# 信封结构检查（有口令时可解头部）
sth inspect carrier.png -p "$(cat pass.txt)"

# 三层校验：宿主完整性 / 信封结构 / AEAD 解密
sth verify carrier.png -p "$(cat pass.txt)"

# 能力与容量确认（写入前）
sth capacity carrier.jpg --safety high --json
```

回归侧：`python scripts/baseline_hash.py --check` 保证默认参数下的字节输出不变；改动任何影响输出的路径都必须先过这一关。详见 [TESTING.md](TESTING.md)。
