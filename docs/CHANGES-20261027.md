### 2026-10-27 12:19:44 - 重构阶段 0：字节级基线 + 三个独立缺陷（B1/B2/B3）+ CI 补 clippy 门禁

**0. 新增 `scripts/baseline_hash.py`（阶段 0 的硬验收工具）**
- 目的：阶段 1 要合并三份 ISOBMFF 解析、搬动格式嗅探，这些改动一旦让写入字节发生偏移，单测未必发现（还原会静默产出不可还原的载体）。脚本把每类载体的**可观测数字**冻结成 JSON，重构后逐项比对。
- 覆盖：`rust/tests/fixtures` + `rust/tests/assets` + `temp/testhevc` 共 **58 例**，release 二进制约 61 s。结构域 44 例成功（HEIF 24、MP4 12、JPEG 4、PNG 2、MKV 2；策略 `item_hidden`/`box_uuid`/`app_segment`/`chunk`/`ebml_void`），14 例按预期不支持（12 条 `.hevc` Annex-B + 1 条 `.hevc10` + 1 个 `.txt`）。
- 记录内容：原始 size/sha256；结构域的 `strategy`、`ube_total_size`、`stego_size`、读回载荷 sha256、**还原后 sha256（44/44 与原文件逐字节相等）**、`inspect --json` 的每策略容量；内容域的 `max/recommended` 容量、读回载荷 sha256。
- 内容域**逐字节比对**：基线用固定 `--seed`（见第 5 节）驱动每次 embed，因此 `content.stego_size` 与新增的 `content.stego_sha256` 都参与严格比对。结构域的 UBE 信封 nonce 始终随机、没有种子开关，那边只比对信封大小、策略、每策略容量与还原是否逐字节相等（44/44 通过）。`--no-seed` 时自动退回"只比大小、不比字节"。
- 用法：`python scripts/baseline_hash.py --write` 冻结，`--check` 比对，`--only <corpus> --limit N` 冒烟。结果在 `temp/baseline/`（gitignored，schema 2）。连续两次 `--check` 已验证 58/58 完全一致（含 5 个内容域产物的字节哈希）；种子与基线不一致时 `--check` 会在起跑前直接报错退出。

**1. B1：HEVC 分支丢掉 `SafetyEnforcement`，`--enforce-safety` 对 HEVC 完全无效**
- 根因：`stego/mod.rs` 的四个 HEVC 调用点传的是 `options.safety.level`，而 PNG/JPEG 传的是整个 `options.safety`；引擎签名 `embed_hevc_with_info(..., safety_level: SafetyLevel)` 也把 enforcement 从类型上抹掉了。
- 修复：签名改为 `safety: SafetyPolicy`（`stego/hevc/engine.rs`），把判定抽成 `enforce_safety(payload_len, recommended, max, policy)`，在容量信息算完之后立即检查；命中返回**新增**的 `StrHideError::SafetyThreshold`（`category()` 复用 `Msg::ErrRejection`，不新增 i18n 词条）。
- 连带修掉一个把错误吃掉的路径：HEIF 分支的兜底是 `Err(_) => heif::embed_heif_bridge(...)`，会把任何错误（含安全拦截、容量不足）替换成桥接器自己的 "No bridgeable image carrier"。改为 `Err(e @ SafetyThreshold(_)) => Err(e)` 直接上抛。
- 实测（`temp/testhevc/test.heic`，推荐 4788 B / 上限 16618 B，载荷 9216 B）：`--enforce-safety` → `[ERROR] 安全策略拦截: Payload (9216 bytes) exceeds safety threshold (4788 bytes) for tier 'high' (carrier maximum is 16618 bytes)`，退出码 1，不产生输出文件；不带该参数 → 照常嵌入并打印 `[WARN] ... Detection risk is elevated`。
- 新增回归测试 `stego::hevc::engine::safety_policy_tests`（3 项，无需语料）：advisory 不拦截、enforced 拦截且报文含两个边界值、等于推荐值时放行。

**2. B2：删除死代码 `stego::sniff::CarrierFormat`**
- 该枚举只有自身文件引用（全库 0 调用点），且缺 `Mp4` 变体，对 MP4 会答 "unsupported"。直接删除 `src/stego/sniff.rs` 与 `stego/mod.rs` 的 `pub mod sniff;`，不修补——阶段 1 会用 `formats::FileFormat` 作为唯一事实源。

- 新增集成测试 `test_lifecycle/facade.rs::structure_read_and_restore_honour_the_overwrite_flag`：拒绝时**不得截断**已存在文件；`_with` 形式覆盖成功；还原结果与原 PNG 逐字节相等。
