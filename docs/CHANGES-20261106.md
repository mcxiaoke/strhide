## 2026-11-06 10:15:06 — WAV 40% 填充率被 working-set ceiling 误拒（回归修复）

- **现象**：`audio_stress -- ../temp/testaudio/07.朔漠南望.wav 8 0.1,0.2,0.4,0.8,1.0` 中 40% 固定失败：`Payload needs 19362654 body slots, above the 18728055 slot working-set ceiling`；10%/20%/80%/100% 通过。
- **数值推导**：WAV 立体声 16-bit 共 24,205,608 样本槽，V4 头占 512 ⇒ `available = 24,205,096`。探针上报 `max_raw_payload_bytes = 3,025,358`（引擎值 3,025,614 减去 R-21 的文件名预留 256 B）。40% 载荷 1,210,143 B + 信封 22 B ⇒ `bits = 9,681,320`，槽丰度 `r = 24,205,096 / 9,681,320 = 2.50018 ≥ 2.5` ⇒ `auto_select_codec` 选 `u = 2`；`slots = 2 × (bits + 7) = 19,362,654`。而 `u = 2` 每槽多 1 个状态位（43 B/槽 vs `u = 1` 的 27 B/槽），768 MiB 上限只容 18,728,055 槽 ⇒ 拒绝。
- **根因**：`plan_body` 先按槽丰度选 `u`，再检查 `max_body_slots(h, u)`，但没有把「该 `u` 的 ceiling」纳入选择。`u = 2` 区间内存在一段载荷（约 1,170,481–1,210,232 B）物理槽够、但 `u = 2` working set 超限的“洞”，探针却按 `u = 1` 定价 `max_raw`。这是**长期缺陷**；本地 40% 固定命中的直接触发是 `541550a`（R-21）把探针容量减去 256 B：40% 从 1,210,246 B（落在洞外，走 `u = 1` 通过）降到 1,210,143 B（落进洞内，走 `u = 2` 拒绝）。代码比对：`max_body_slots`、`MAX_WORKING_SET_BYTES`、`auto_select_codec` 阈值自 WAV 引擎引入以来未变；`541550a^` 的公共 probe 直接返回引擎值。用当前二进制实测 1,210,246 B 通过、1,210,143 B 复现原错误，确认边界翻转。
- **修法**：`plan_body` 在选中 `u` 后若 `slots > max_body_slots(h, u)` 且 `u > min_u`，回退到 `min_u`（WAV 为 `u = 1`，每槽 27 B，ceiling 29,826,162 槽）重新计算。未改 wire、公开 API、错误类型与探针容量；`u` 由写入头 `stc_u` 携带，提取端照常恢复。FLAC（`min_u = 3`）路径不受影响。代价：洞内载荷的 `u` 从 2 降为 1，预期改变率约 0.26→0.50 flips/bit，换取“探针报得出的容量都写得进”。
- **验收**：新增 `wav_plan_falls_back_to_u1_when_u2_exceeds_the_working_set`（固定 40% 的实际数值与 `u = 2` 洞两侧边界）；禁用回退时该用例以 `u = 2` 失败，恢复后通过。`audio_stress` 10%/20%/40%/80%/100% 全部 `ok`（0 failed），每轮 embed→extract 载荷 SHA-256 一致。
