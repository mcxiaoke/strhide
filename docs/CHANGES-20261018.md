### 2026-10-18 21:00:18 - CLI：write/remove 支持多载体（`-c` 可变参数），恢复 `-s` 短选项
- **背景**: 需要一次处理多个文件。选择把 `-c` 改为可变参数，而不是新增 `--batch`——后者只是一个冗余的"参数个数开关"，还得在五个子命令各加一次校验；`-c a.png b.png` 与 `-c a.png -c b.png` 天然都支持，单载体用法与输出完全不变。
- **`rust/src/cli.rs`**:
  - `WriteArgs.carrier` / `RemoveArgs.carrier` 改为 `Vec<PathBuf>`（`num_args = 1..`）。
  - `write`: 载荷只解析一次（`PayloadSource::into_buffered()`），同一份载荷写入每个载体；`--strategy ask` 与多载体互斥（配置文件里的 `strategy = "ask"` 同样被拦——检查放在 CLI 与 config 合并之后）；多载体时 `-o` 必须是**已存在的目录**。
  - `remove`: 逐个剥离，多载体时 `-o` 同样要求目录，默认仍为原地还原。
  - 新增 `for_each_carrier`（单载体不打印汇总，输出与之前逐字节一致；多载体首次失败即停，打印 `[SUMMARY] n/m carriers succeeded; k not attempted.`）、`batch_output_dir`、`carrier_output_path`、`preflight_batch`、`print_write_result`/`print_remove_result`。
  - `preflight_batch` 在改动第一个载体前拦下：文件不存在、是目录、格式未识别、同一载体重复列出、两个载体映射到同一输出。容量不足与"已含隐藏数据"只能由引擎逐载体判定，故仍可能中途失败——每个载体的写入/剥离是原子操作，报告因此准确（已完成的保持修改，其余未触碰）。
  - 恢复 `-s` 短选项（`short = 's'`）：Python 版一直有（`python/strhide/cli.py:454`），Rust 重写时丢失，而 README 与历史设计文档仍按 `-s` 书写，导致照文档敲 `-s auto` 会报 unexpected argument。
- **`rust/src/engine.rs`**: 新增 `PayloadSource::Buffered { data, filename, is_file }` 与 `PayloadSource::into_buffered()`，把"来源 → 字节"的推导（含 `Text` 的 NFC 规范化、`Stdin` 只读一次）收敛到一处，`write_carrier` 改为调用它（消除重复逻辑）。批量写入因此不会把空 stdin 嵌进第二个载体（原实现每次调用都 `read_to_end`），也不会把 `-d` 的文件名退化成 `payload.bin`（`Bytes` 分支硬编码该名字）。
- **文档**: README（中英）新增批量示例与特性条目、修正 `strhide list -c` → `strhide inspect -c`（`list` 命令早已并入 `inspect`）、标注 `-s ask` 仅限单载体；`rust/README.md` 同步并移除已废弃的 "generic EOF fallback for any other file" 表述。
