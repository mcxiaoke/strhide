# 现代图像（WebP/AVIF/HEIC）与视频（MP4/MKV）传统非 AI 大容量隐写术全案指南

> **核心定位校准：** 基于深度学习的隐写术（如 VideoSeal、TrustMark）本质上是**高鲁棒数字水印**，为了抵抗平台暴力转码而牺牲了容量（通常仅 $100 \sim 1024\text{ bits}$）。而当你需要隐藏**几十 KB 乃至数 MB 的加密文件、代码或长报文**（且通过网盘、即时通讯原文件、邮件附件或私有信道传输，不经历第三方平台二次有损重编码）时，**传统算法级隐写术**才是唯一的工业级解法。

---

## 一、 底层同源性校准：为什么现代图片和视频在数学上是同一件事？

在设计针对 WebP、HEIC、AVIF 和 MP4/MKV 的传统隐写算法前，必须明确一个核心工程事实——**现代主流图片格式本质上就是“单帧封装的视频关键帧（I-Frame）”**：

* **WebP（有损）** $\iff$ **VP8 视频编码**的帧内编码（Intra-frame）宏块；
* **HEIC / HEIF** $\iff$ **HEVC (H.265) 视频编码**的帧内编码单元（CU/TU）；
* **AVIF** $\iff$ **AV1 视频编码**的帧内编码超块（Superblock）。

### 有损编解码管线的“隐写生死线”

无论是上述哪种格式，在有损压缩模式下都严格遵循以下五步数学管线：

$$\text{原始像素 (RGB/YUV)} \xrightarrow{1.\text{ 空间/时间预测}} \text{预测残差} \xrightarrow{2.\text{ 正交变换 (DCT/DST/ADST)}} \text{频域实数系数} \xrightarrow{3.\text{ 除以量化步长 } Q \text{ 并取整}} \mathbf{\text{整数量化系数 (QDCT)}} \xrightarrow{4.\text{ 熵编码 (CABAC/算术编码)}} \text{最终文件码流}$$

* **常见新手误区（必败做法）：** 将有损 `.webp`、`.heic` 或 `.mp4` 解码成 RGB 像素 $\rightarrow$ 修改像素 LSB $\rightarrow$ 重新调用有损编码器保存。
  * **失败原因：** 步骤 $1 \sim 3$ 是不可逆的有损过程（包含色彩空间转换舍入误差与除以量化步长 $Q$ 后的四舍五入）。你在空域像素上修改的微弱比特，在经过第 $3$ 步量化取整时会 $100\%$ 被抹平清零。
* **唯一正确的传统隐写切入点：**
  1. **频域/码流层拦截（针对有损格式）：** 必须卡在**步骤 $3$（量化取整之后）与步骤 $4$（无损熵编码之前）**，直接修改整数量化系数、帧内预测方向或运动矢量，随后直接送入算术编码器打包。
  2. **无损压缩管线（针对现代图像）：** 直接开启现代图像格式原生支持的**真无损模式（Lossless Mode）**，绕过有损量化，直接在像素域执行高阶自适应矩阵隐写。

## 二、 现代图像格式（WebP / AVIF / HEIC）非 AI 隐写方案全景对比

针对静态现代图像，传统大容量隐写共有三大成熟技术路线：

| 方案维度 | 方案 A：真无损模式 + 空域自适应隐写 | 方案 B：有损量化系数隐写 (QDCT/QDST) | 方案 C：帧内预测模式隐写 (IPM Stego) |
| :--- | :--- | :--- | :--- |
| **适用格式** | WebP (`VP8L`), HEIC Lossless, AVIF Lossless | 有损 WebP (`VP8`), 有损 HEIC (`HEVC`), 有损 AVIF (`AV1`) | 有损 HEIC (`HEVC`), 有损 AVIF (`AV1`), 有损 WebP |
| **单图隐写容量 ($1080\text{p}$)** | **极大**（$30\text{ KB} \sim 150\text{ KB}$） | **大**（$5\text{ KB} \sim 25\text{ KB}$，取决于质量因子 QF） | **中等**（$1\text{ KB} \sim 5\text{ KB}$） |
| **开发与魔改难度** | ⭐（纯 Python/Rust 调库即可，无需改编解码器 C 源码） | ⭐⭐⭐（需修改 `libwebp` / `x265` / `libaom` 系数层） | ⭐⭐⭐⭐（需介入编码器率失真优化 RDO 决策环路） |
| **视觉无损度 (PSNR)** | 极高（$> 52\text{ dB}$，肉眼绝对不可见） | 高（$42 \sim 48\text{ dB}$，纹理区微弱噪点变化） | **极高**（编码器自动通过残差补偿画面，几乎零画质损失） |
| **文件体积影响** | 文件比有损图大（但比传统 PNG 小 $25\% \sim 35\%$） | 体积几乎不变（误差在 $\pm 1\%$ 以内） | 体积轻微膨胀（约增加 $2\% \sim 5\%$ 码率） |
| **抗盲检测能力** | 极高（配合 `HILL`/`WOW` 选位，且避开传统 JPG 扫描器） | 高（需严格遵守非零系数修改与零系数保护） | **极高**（不产生异常频域残差，传统统计分析完全失效） |

---

### 1. 方案 A 详解：真无损模式（Lossless）+ 空域自适应矩阵编码（工程首选）

* **技术原理：**
  WebP、HEIC 和 AVIF 标准均原生定义了无损压缩算法。例如无损 WebP（`VP8L`）采用空间预测变换、色彩去相关变换与二维 LZ77 + 霍夫曼编码，其像素值在解码后与写入前 **$100\%$ 比特级一致**。
* **完整实现流：**
  1. 解码图像获取 RGB 矩阵，利用 `conseal` 库中的 **`HILL`** 或 **`S-UNIWARD`** 算法计算每个像素的失真代价 $\rho$（自动锁定树叶、毛发、噪点等高复杂度纹理区，避开平滑背景）。
  2. 将待隐藏文件经 `ChaCha20` 流加密后，配合密钥派生的伪随机数生成器（CSPRNG）打乱候选像素顺序。
  3. 采用 **$\pm 1$ 三进制汉明码（Matrix Embedding）** 或 **STC（综合症网格码）** 修改像素最低有效位。
  4. 调用图像库以 `lossless=True` 保存为 `.webp`、`.heic` 或 `.avif`。
* **核心优缺点校准：**
  * **优点：** 无需编译或修改庞大的 C/C++ 编解码器源码，几百行 Python/Rust 即可落地；容量极大；天然免疫所有针对 JPEG DCT 频域设计的盲检测器。
  * **缺点：** 生成的文件带有无损标识（如 WebP 的 `VP8L` 块头），文件体积虽小于 PNG，但大于常规有损压缩图。

### 2. 方案 B 详解：有损频域量化系数隐写（QDCT / QDST 注入）

* **技术原理：**
  * **WebP (`libwebp`)：** 有损 WebP 将图像划分为 $16 \times 16$ 宏块（含 $4 \times 4$ 亮度与色度子块），执行离散余弦变换（DCT）与沃尔什-哈达玛变换（WHT）。在 `src/enc/quant_enc.c` 的 `VP8EncQuantizeBlock()` 完成量化取整后，筛选绝对值 $|c_i| > 1$ 的非零交流系数（AC Coefficients）进行矩阵嵌入。
  * **HEIC (`x265`) / AVIF (`libaom`)：** 拦截变换单元（Transform Unit, TU）中的量化系数矩阵，结合类似 `J-UNIWARD` 的局部能量评估挑选嵌入位置。
* **核心防坑校准（Shrinkage 零值坍缩问题）：**
  * **严禁将值为 $0$ 的系数改为 $\pm 1$：** 自然有损图像中大量的量化系数为 $0$，强行改非零会严重破坏零系数直方图分布，且显著增加文件体积。
  * **严禁将值为 $\pm 1$ 的系数减为 $0$：** 若把 $1$ 或 $-1$ 改成 $0$，解码器在读取时无法区分“原本就是 $0$ 的跳过位”与“被隐写改成 $0$ 的有效位”（即 `F5` 算法著名的 Shrinkage 问题）。工程上**只允许对 $|c_i| \ge 2$ 的非零系数进行修改**，或采用湿纸编码（Wet Paper Codes / STC）规避。

### 3. 方案 C 详解：帧内预测模式隐写（IPM Steganography，HEIC/AVIF 高阶方案）

* **技术原理：**
  现代编码器为了极限压缩，在编码一个图像块前会先用周围已编码的像素来“预测”当前块的方向：
  * **HEIC (HEVC)** 拥有 **$35$ 种帧内预测模式**（Planar、DC 以及 $33$ 个精细角度方向）。
  * **AVIF (AV1)** 拥有 **$56$ 种帧内方向预测模式**。
  * **嵌入方法：** 当编码器通过率失真优化（RDO）算出某纹理块的最优预测模式为偶数（如模式 $18$），而你要嵌入的秘密比特为 $1$ 时，强行命令编码器改用相邻的奇数次优角度（如模式 $17$ 或 $19$）进行预测。
* **核心优缺点校准：**
  * **为什么它极难被检测？** 当你强行换了一个相近的预测角度后，编码器紧接着会自动计算“新预测画面与真实画面的残差”，并把这点细微差别通过残差系数补齐！最终解码出来的像素画面几乎没有任何人为注入的孤立噪点，所有像素统计规律完全符合编码器标准语法。
  * **缺点：** 因为没有选用理论最优预测角度，残差能量会略微变大，导致最终文件体积上升 $2\% \sim 5\%$；且必须修改编码器源码中的模式决策函数。

## 三、 现代视频格式（MP4 / MKV - H.264 / HEVC / AV1）非 AI 隐写方案全景对比

视频相比静态图像引入了**时间维度（帧间预测与运动补偿）**和**多轨容器封装**，在传统隐写中有五大成熟流派：

| 方案名称 | 隐写作用层 | 10秒 $1080\text{p}$ 视频容量 | 视觉失真与帧间漂移控制 | 抗检测隐蔽性 | 工程实现难度 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **1. 运动矢量隐写 (MV Stego)** | P 帧 / B 帧运动矢量 $(mv_x, mv_y)$ | **大**（$50\text{ KB} \sim 200\text{ KB}$） | **无漂移**（需在编码环路内重算残差） | ⭐⭐⭐⭐⭐（极高，行业公认首选） | ⭐⭐⭐ |
| **2. 非参考帧残差隐写 (QDCT)** | B 帧 / I 帧量化残差系数 | **极大**（$200\text{ KB} \sim 1.5\text{ MB}$） | **仅改非参考 B 帧无漂移**；直接改 I/P 帧会产生严重漂移 | ⭐⭐⭐⭐（配合纹理自适应与矩阵编码） | ⭐⭐⭐ |
| **3. 编码块划分结构隐写 (CU/PU Partition)** | HEVC/AV1 四叉树/多叉树分割标志 | 中（$10\text{ KB} \sim 40\text{ KB}$） | **绝对零漂移**（编码器原生自适应补偿） | ⭐⭐⭐⭐⭐（码流语法合法，像素无噪点） | ⭐⭐⭐⭐ |
| **4. 熵编码旁路隐写 (CABAC Bypass)** | 已压缩码流的符号位/尾数位 | 中（$20\text{ KB} \sim 80\text{ KB}$） | 需严格筛选高频块尾部系数，否则局部有伪影 | ⭐⭐⭐（速度最快，无需完全重编码） | ⭐⭐⭐⭐ |
| **5. 容器内无损音轨隐写 (Audio Track)** | MP4/MKV 内的 FLAC/ALAC 音轨采样 | **极大**（$100\text{ KB} \sim 500\text{ KB}$） | **视频画面 $100\%$ 原封不动**，音频听觉无损 | ⭐⭐⭐⭐（彻底绕过视频画面分析器） | ⭐（极简） |

---

### 1. 方案 1 详解：运动矢量隐写（Motion Vector Stego —— 视频隐写皇冠方案）

* **技术原理：**
  在 H.264、HEVC 和 AV1 中，P 帧与 B 帧不直接存储完整画面，而是记录当前宏块相比参考帧移动了多少距离，即运动矢量 $\mathbf{mv} = (mv_x, mv_y)$。现代编码器普遍采用 **$1/4$ 像素（Quarter-pel）精度**（即整数值 $1$ 代表实际画面移动 $0.25$ 个像素）。
  * **选位策略：** 挑选幅值较大（例如 $\sqrt{mv_x^2 + mv_y^2} > \text{Threshold}$，代表画面正在快速运动，人眼对快速运动物体的微小位移完全不敏感）的宏块。
  * **嵌入方式：** 对 $mv_x$ 或 $mv_y$ 的 $1/4$ 像素尾数进行 $\pm 1$ 微调（结合汉明码矩阵嵌入）。
* **核心防坑校准（In-Loop 闭环补偿原则）：**
  * **必须在编码环路内（In-Loop）修改：** 正确做法是在编码器完成运动估计（Motion Estimation）算出最优 $\mathbf{mv}$ 后，**立即修改 $\mathbf{mv}$**，然后让编码器用修改后的 $\mathbf{mv}'$ 去参考帧取块并计算残差（Residual）。这样你人为制造的 $0.25$ 像素偏移会被编码器接下来的残差编码自动补偿掉，不仅画质毫无损失，而且后续帧也不会出现累计误差！

### 2. 方案 2 详解：量化残差系数隐写（QDCT —— 解决“帧间漂移失真”是关键）

* **技术原理：**
  与静态图像类似，直接修改视频帧经过 DCT/DST 变换量化后的非零整数残差系数。
* **核心防坑校准（Drift Error 帧间漂移灾难）：**
  * **致命错误：** 如果你在已经编码好的 H.264/HEVC 码流上直接解析并修改 I 帧或 P 帧的残差系数，由于视频的 P 帧依赖前一帧作为参考，I 帧上 $1$ 个像素的微小误差会沿着运动轨迹在接下来的几十个 P 帧里不断叠加放大（像滚雪球一样），导致视频播放几秒后出现肉眼可见的色块撕裂与模糊（即 **Drift Error 漂移失真**）。
  * **两种工程解法：**
    1. **只修改非参考 B 帧（Non-reference B-frames）：** B 帧如果本身不被其他帧用作参考帧，修改其残差系数**绝对不会向后传播误差**，误差在该帧播放完后立即终结。
    2. **编码环路内（In-Loop）重建：** 在编码器内部修改完当前帧的 QDCT 系数后，立即送入编码器内置的反量化与反变换模块（IDCT）更新本地参考帧缓冲区（Decoded Picture Buffer, DPB），从而彻底消除解码端与编码端的失配。

### 3. 方案 3 详解：编码单元划分结构隐写（CU/PU Partition Stego —— H.265/AV1 专属）

* **技术原理：**
  H.265 (HEVC) 引入了编码树单元（CTU），通过四叉树（Quadtree）将 $64 \times 64$ 的块递归划分为 $32 \times 32$、$16 \times 16$ 直至 $8 \times 8$；AV1 更是支持多达 $10$ 种多叉树划分形态。
  * 在纹理适中的区域，将 $16 \times 16$ 块保持原样（代表比特 `0`）与拆分成四个 $8 \times 8$ 子块（代表比特 `1`），两者的率失真代价（RD Cost）极其接近。
  * 通过密钥控制特定位置的块划分标志位（`split_cu_flag`），在完全不篡改任何残差系数或像素的前提下嵌入信息。
* **优缺点校准：** 解码端只需读取语法树中的块划分结构即可瞬时提取数据，无需做频域变换，且生成的画面完全是编码器标准输出，对基于像素残差的深度学习检测器（如 SRNet）具有极强的免疫力。

### 4. 方案 4 详解：熵编码语法元素旁路隐写（CABAC Bypass Stego）

* **技术原理：**
  H.264/HEVC 使用基于上下文的自适应二进制算术编码（CABAC）。普通语法元素强依赖上下文概率模型（改一个 bit 会导致后续算术解码全部错位崩溃）；但标准专门设计了**等概率旁路模式（Bypass Mode）**，用于编码近似均匀分布的语法元素（如非零系数的正负符号位 `coeff_sign_flag`、高幅值系数前缀后缀等）。
* **优缺点校准：** 可以在不经过完整像素级解码和重编码（Transcoding）的情况下，仅通过熵解码器解析出语法流、修改高频尾部微小系数的旁路比特后再重新做算术打包。速度比全量重编码快 $10$ 倍以上，但需严格筛选只改高频尾部的 $\pm 1$ 系数符号，否则易引起局部振铃伪影。

### 5. 方案 5 详解：容器内无损音轨混合隐写（Audio Track Stego —— 极简高容量工程捷径）

* **技术原理：**
  MP4 和 MKV 是多媒体**容器（Container）**，内部包含独立的视频流（Video Stream）和音频流（Audio Stream）。
  * MP4 原生支持封装 **ALAC（Apple Lossless 无损音频）** 或 **FLAC**；MKV 支持 **FLAC** 与 **WAV (PCM)**。
  * 保持视频 H.264/HEVC 码流 $100\%$ 不动（`ffmpeg -c:v copy`），仅将音轨提取出来，在音频 $16\text{-bit}$ 或 $24\text{-bit}$ 采样点的复杂高频掩蔽区（利用心理声学模型或局部方差自适应）通过矩阵编码注入加密数据，再以无损音频编码封回 MP4/MKV。
* **核心优缺点校准：**
  * **优点：** 开发难度极低（无需触碰复杂的视频编码器 C 源码，纯 Python 即可完成）；视频画质 $100\%$ 零修改；容量极大（$1$ 分钟双声道 $48\text{kHz}$ 音频仅按每采样点 $0.1\text{ bit}$ 的超低安全嵌入率，即可稳定隐藏 **$70\text{ KB} \sim 150\text{ KB}$** 数据）。
  * **缺点：** 要求视频本身带有正常环境音或背景音乐（不能是静音视频），且文件必须作为原文件传输，不能被平台剥离音轨或重压为低码率 AAC。

## 四、 工程落地校准：技术选型决策树与轻量化开源改造底座

如果你不想从零啃几百万行代码的 `FFmpeg` 或 `x265` 源码，以下是针对不同载体需求、**代码量最小且最易魔改**的开源工程底座与选型建议：

### 1. 推荐拿来魔改的轻量级开源编解码底座

* **针对 WebP 图像：**
  * **无损路线（推荐）：** Python `Pillow` / Rust `image` + `conseal`（计算 `HILL` 代价）+ 自定义 STC/汉明码模块。
  * **有损频域路线：** Google 官方 **`libwebp`**（C 语言，代码结构极度清晰，只需改 `src/enc/quant_enc.c` 和 `src/dec/frame_dec.c` 两个文件中的量化系数数组接口）。
* **针对 HEIC / AVIF 图像：**
  * **无损路线：** Python `pillow-heif` / `pillow-avif-plugin`（开启 `quality=-1` 或 `lossless=True`）。
  * **有损路线：** 结合 Rust 编写的纯正 AV1 编码器 **`xiph/rav1e`**（代码模块化远好于 C 语言的 `libaom`，非常适合用 Rust 安全地插入私有系数置换逻辑）。
* **针对 MP4/MKV 视频：**
  * **如果走视频码流层（MV / QDCT）：** 强烈推荐使用单头文件开源 H.264 编码器 **`lieff/minih264`**（整个 H.264 编码器浓缩在单个 `minih264e.h` 头文件中，仅几千行 C 代码，定位运动矢量与量化残差只需 $10$ 分钟！）或思科开源的 **`cisco/openh264`**。
  * **如果走容器音轨层：** Python `PyAV`（FFmpeg 绑定）+ `soundfile`（读写 FLAC/ALAC 采样）。

### 2. 最终方案选型速查表

1. **想藏几十 KB 文件在现代图片里，且一天内写完代码：**
   $\rightarrow$ 选 **WebP / HEIC / AVIF 真无损模式 + `HILL` 纹理自适应 + $(7,4)$ 汉明码 + `ChaCha20` 加密洗牌**。
2. **想藏几十 KB 文件在有损小体积 WebP 里：**
   $\rightarrow$ 选 **魔改 `libwebp` 的 `VP8EncQuantizeBlock` 函数**，对 $|c_i| \ge 2$ 的非零系数做矩阵嵌入。
3. **想在 MP4/MKV 视频里藏几百 KB 数据，且不想碰 C/C++ 视频编码器：**
   $\rightarrow$ 选 **MP4/MKV 视频流直接 Copy + 无损音轨（ALAC/FLAC）自适应矩阵隐写**。
4. **想打造专业级纯视频码流隐写（无音轨也可藏数据，且抗专业视频取证）：**
   $\rightarrow$ 选 **魔改 `minih264` 或 `x265` 的环路内（In-Loop）运动矢量（MV）+ 非参考 B 帧残差隐写**。
