# 变更记录 2026-10-19

### 2026-10-19 11:27:00 - 架构重构：基于内置固定密钥（BUILTIN_DEFAULT_KEY）的全加密统一信封管线，消除磁盘明文泄露

- **背景与架构决策**:
  - 用户指出：“实现两套反而搞复杂了，如果不存在明文模式，明文模式用代码内固定密钥代替呢，并不会降低安全性吧”。
  - 彻底废除磁盘上的“无加密明文信封”分支，统一信封管线：所有写入磁盘的信封均经过 Deflate 压缩与 AES-256-GCM 高强度加密，用户未指定口令时使用内置固定密钥 `BUILTIN_DEFAULT_KEY`。
  - 用户无感感知：未设密码时无需输入密码直接提取与还原；对外界（十六进制编辑器、YARA、取证工具）而言，载体内除魔数外全为高熵密码学随机密文，彻底抹除原宿主 SHA-256、元数据明文文件名、载荷明文及结构性断层。
  - 100% 确定性保证与向下兼容：保持对历史 v0.2/v0.3 遗留未加密明文信封的兼容回退读取与还原，可靠性达到 100%。
- **`rust/src/crypto.rs`**:
  - 新增内置公开密钥常量 `BUILTIN_DEFAULT_KEY = "strhide::envelope::v2::default::builtin::public::secret"`。
- **`rust/src/envelope.rs`**:
  - `pack_with_stealth_mask`：在无密码默认模式下，自动使用 `BUILTIN_DEFAULT_KEY` 对 Header 敏感字段（版本、标志、原宿主 SHA-256、大小与偏移量）执行掩码保护。
  - `unpack_with_password`：解包时优先尝试用户密码掩码（stealth 模式），再尝试 `BUILTIN_DEFAULT_KEY` 掩码（默认模式），最后回退到标准原始 unpack（兼容旧版载体）。
- **`rust/src/engine.rs`**:
  - `write_carrier`：统一使用 `effective_password = password.unwrap_or(BUILTIN_DEFAULT_KEY)`，元数据与载荷数据流无条件经 AES-256-GCM 加密，精确计算统一信封体积。`WriteResult.is_encrypted` 映射为 `has_custom_password`，用户感知符合“无需密码”。
  - `read_carrier`：在未设置加密标志时自动采用 `BUILTIN_DEFAULT_KEY` 派生密钥进行解密；若解密失败（针对历史未加密明文载体），透明安全回退至明文解码，保证绝对向后兼容。
  - `inspect_carrier`：未设密码信封使用 `BUILTIN_DEFAULT_KEY` 解密元数据并安全回退明文，报告 `is_encrypted: Some(false)`。
  - 公开 `CarrierMetadata::encode_compact` 和 `decode_compact` 便于生态测试与工具集成。
- **测试与验证**:
  - `rust/tests/stealth_defingerprinting.rs`：
    - 新增 `test_default_carrier_uniform_encryption_and_zero_plaintext`：验证默认无密码写入时，载体文件中绝对不存在原宿主 SHA-256、载荷明文字符串和元数据文件名；且无密码读取、检查、验证、还原 100% 成功，还原载体与原图逐比特一致；
    - 新增 `test_legacy_unencrypted_carrier_backward_compatibility`：手工合成历史未加密明文信封注入载体，验证读取引擎 100% 成功解码并逐比特无损还原。
  - 更新 `rust/tests/compact_meta.rs` 与 `rust/tests/fixes_regression.rs` 中的断言以适配全加密信封。
  - `cargo clippy --all-targets` 0 警告，`cargo fmt` 格式化规范，全量 111 个回归测试全部 PASS。

### 2026-10-19 10:50:54 - 隐蔽性增强：信封头部敏感字段与尾标 CRC 密码学掩码（去指纹化与反特征扫描）
- **背景**: 用户指出当前的 magic 与 header 特征过于明显。深入核对发现现有实现存在深层取证破绽：
  1. 即使在 `--stealth` 模式下，112 字节固定头部除前 8 字节派生魔数外，其余 104 字节全盘明文裸露，尤其是偏移 `+48` 处的 32 字节原宿主 SHA-256 哈希，使取证人员无需密码即可直接比对验证隐藏信封的存在；
  2. 头部包含大量带有 `0x00` 填充的小整数偏移量与尺寸，呈现出极具指纹特征的高低熵交替断层；
  3. 24 字节 Trailer 包含公开 IEEE 802.3 标准 CRC32，任何扫描脚本只需对 24 字节滑动窗口验证 `crc32(window[0..16]) == window[16..20]` 即可直接定位信封。
- **设计与可靠性保证**:
  - 核心约束：定性与可靠性第一。所有修改必须保持 100% 确定性、逐比特无损可逆还原，并保持对历史信封的 100% 向下兼容。
  - 编制完整技术方案与实施规范文档 `docs/envelope_header_magic_stealth_redesign_20261019.md`。
- **`rust/src/crypto.rs`**:
  - 新增 `derive_header_mask(password, salt) -> [u8; 76]`：利用 PBKDF2 与 HKDF-Expand (`b"strhide-header-mask-v1"`) 派生 76 字节确定性流密钥掩码。
  - 新增 `derive_trailer_crc_mask(trailer_magic) -> u32`：从密码派生的 4 字节尾标魔数中确定性派生 CRC32 掩码。
- **`rust/src/envelope.rs`**:
  - `EnvelopeHeader`：
    - 新增 `pack_with_stealth_mask(password)`：在 stealth 模式下，对 Header 中除了 `magic_header` (8B)、`salt` (16B)、`base_nonce` (12B) 之外的所有 76 字节敏感字段（`version`, `flags`, `strategy_id`, `orig_host_size`, `orig_host_sha256`, 注入偏移与尺寸等）执行 XOR 流加密。在载体文件中呈现为完美的 112 字节伪随机密文，彻底抹除原宿主 SHA-256、版本号和全零填充结构。
    - 新增 `unpack_with_password(data, password)`：带密码读取时，根据 `salt` 自动解密还原 Header；若未掩码或解密版本不符，安全回退到标准 `unpack`，无缝兼容旧版未掩码信封。
  - `EnvelopeTrailer`：
    - 新增 `create_stealth(ube_offset, ube_total_size, trailer_magic)`：在 stealth 模式下将真实 CRC32 异或 `trailer_crc_mask`，彻底破坏公开 CRC32 扫描窗口。
    - `unpack`：支持检验带掩码 CRC 与传统明文 CRC，保证 100% 双向兼容。
- **`rust/src/engine.rs`**:
  - `write_carrier`、`read_carrier`、`remove_carrier`、`inspect_carrier`、`verify_carrier` 全面升级为基于密码感知的头部/尾标打包与解包。
- **测试与验证**:
  - 新增集成测试 `rust/tests/stealth_defingerprinting.rs`（3 项全绿）：
    1. `test_stealth_carrier_leaks_no_host_sha256`：验证载体中绝对不包含原宿主 32 字节 SHA-256 明文，且提取与逐比特还原无误；
    2. `test_stealth_trailer_breaks_public_crc32_scan`：验证外部标准 IEEE 802.3 CRC32 滑动窗口扫描 100% 无法检出尾标；
    3. `test_stealth_legacy_unmasked_backward_compatibility`：验证旧版未掩码 stealth 载体可被新版本 100% 成功读取并逐比特还原。
  - `cargo test` 全量回归测试 109 项全部 PASS，0 失败。
