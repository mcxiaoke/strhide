## 0. 结论

1. **载荷 ≤ 推荐值**：`IMG_0033.MOV` VMAF **99.99**、SSIM 0.9984，且 **385 帧里有 193 帧逐像素完全相同**（载荷只落在非参考帧上）——肉眼不可能看出。`VID_20261007` 推荐 43 KiB 时 VMAF **97.9**、SSIM 0.9977，也属于"并排都很难分辨"。
2. **载荷 ≈ 2.5 倍推荐值**：VMAF 掉到 **94.5**、PSNR 38.3 dB，进入"有经验的人并排能看出"的区间。**这是可用的上限，不是推荐值。**
3. **载荷 = 极限容量（8.9 倍）**：VMAF **77**、PSNR 31.5 dB，整块 TU 级偏移可见（见 §3 的放大差分图）。极限容量是"能塞进去"的硬上限，不是画质承诺。
4. **画质恶化不是渐进的，是在跨过 band 边界时跳变的**：推荐值以内载荷只吃非参考帧（零漂移）；一旦吃满，就进入参考帧，误差被后续帧持续预测，同时 STC 被迫启用高代价槽位（大幅值系数翻转 → 整个变换块偏移）。这解释了 PSNR 从 48.7 → 38.3 的陡降。

## 1. 怎么评估（四层，缺一不可）

| 层 | 指标 | 判读 | 为什么需要 |
| :--- | :--- | :--- | :--- |
| 1 客观总量 | PSNR / SSIM / VMAF | 见 §1.1 阈值 | 快速、可复现、可进 CI |
| 2 时间分布 | 逐帧 PSNR 的 min / p05 / σ | σ 大 = 误差集中在少数帧 | 平均 PSNR 会掩盖"某几帧很糟" |
| 3 单样本误差 | mean\|Δ\|、p99.9、>8 级像素占比、单帧 max\|Δ\| | 见 §2.3 | PSNR 是能量口径，而"块状感"来自少数大偏移 |
| 4 目视 / 主观 | 差分图 ×12 放大 + ABX 盲测 | 见 §3 | 指标只能筛，最终判据是人眼 |

### 1.1 经验阈值（1080p / 8-bit / 观看距离 1.5~2 倍屏高）

| VMAF | SSIM | PSNR | 判读 |
| ---: | ---: | ---: | :--- |
| ≥ 98 | ≥ 0.998 | ≥ 45 dB | 几乎不可区分（本方案的推荐值档位） |
| 95 ~ 98 | 0.995 ~ 0.998 | 40 ~ 45 dB | 并排仔细对比才能看出 |
| 90 ~ 95 | 0.985 ~ 0.995 | 35 ~ 40 dB | 有经验者能看出 |
| < 85 | < 0.97 | < 32 dB | 明显可见，不可交付 |

VMAF 用 Netflix 官方 `vmaf_v0.6.1` 模型（libvmaf 无内置模型，需下载 JSON，见 §5）。

**为什么这个载体的曲线平缓得多**：它没有非参考帧，载荷天然摊在 802 个参考帧上，每帧翻转数低；而 `IMG_0033.MOV` 的非参考帧池只有 837 K 槽，吃满后立刻溢出到参考帧。结论：**曲线陡不陡，取决于"每帧翻转密度"，不是载荷绝对值**。

## 3. 目视证据

`temp/quality_sweep/panel_40k.png`（推荐值，差分 ×12）：右栏的误差**贴着物体轮廓与纹理走**，平坦路面几乎全黑——正是掩蔽效应最强的位置。

`temp/quality_sweep/panel_max.png`（极限容量）：右栏误差铺满了整片路面，左中两栏在中灰路面上可以直接看出**方形块状/棋盘纹**，与 PSNR 31.5 dB、VMAF 77 一致。

生成方式：取同一帧、同一 320×200 区域，左=原图，中=隐写，右=|Δ|×12。

## 4. 一个需要知道的副作用：隔帧差异

推荐值以内载荷只落在**非参考帧**上，而参考帧完全未改。`IMG_0033.MOV` 的 GOP 里两类帧是交错的，所以"改动量"在时间轴上隔帧起伏。实测没有可见影响（VMAF min 97.4，逐帧 PSNR σ 1.77 dB），但这是本设计的固有形态：

- 好处：一半帧是**逐字节原样**，任何针对"整段视频都变了"的检测都不成立。
- 风险：如果将来把 band 0 预算推得更高、单帧误差接近可见阈值，就可能出现 30/60 Hz 的闪烁感。
- 若在意：把预算跨全部可写帧平摊（放弃"一半帧不动"的特性），代价是每帧都被修改。

## 5. 复现

```bash
# VMAF 模型（libvmaf 无内置模型）
curl -sSL -o temp/vmaf/vmaf_v0.6.1.json \
  https://raw.githubusercontent.com/Netflix/vmaf/master/model/vmaf_v0.6.1.json

# 一条命令跑完整条曲线（产物在 temp/quality_sweep/<carrier>/）
python scripts/hevc_quality_sweep.py \
  --carrier temp/testhevc/IMG_0033.MOV \
  --payloads 1024,5120,15360,40600,102400,362800 \
  --metrics psnr,ssim,vmaf
```

输出：控制台表格 + `sweep.json`（汇总）+ `psnr_per_frame_<size>.csv`（逐帧）。

## 6. 局限

- VMAF 模型在 1080p 压缩失真上训练，对"内容自适应隐写"这类极稀疏、非均匀的扰动**没有专门标定**，只能当近似判据；判"不可见"时它偏宽松（本方案靠 PSNR/单样本误差与目视交叉验证）。
- VMAF 的 temporal pooling 很弱，**不建模闪烁**；§4 的隔帧形态要靠逐帧曲线人工判断。
- 主观 ABX 未纳入本次测量（需要多人多轮），结论中"能看出/看不出"均来自客观指标 + 单帧差分目视，属工程判断而非正式主观实验。
