## 一、方案背景与架构重构目标

在当前 `strhide` 架构中，为了在提取端重现 UERD 槽位排序，系统引入了二元类桶约束（`|c| & !1`），导致了三个致命后果：
1. **方向锁死**：正偶数只能 $+1$，正奇数只能 $-1$，丧失了三元自由度；
2. **极化失效**：专为三元设计的维纳代价极化在二元锁死下发生畸变，加剧了 DCTR 8000 维频域特征漂移；
3. **结构指纹**：类边界单向门移动产生了高达 $9\sigma$ 异常的统计赤字人造指纹。

**本方案目标**：彻底废弃二元类桶架构，全面迁移至学术界通用的**“全图非零系数伪随机置换 + 全图三元 STC 嵌入（模式 A）”**标准架构，实现学术正统性、高隐蔽性与 100% 盲提取的统一。

## 二、真实性能基准测试与可行性证明

针对“全图展开 STC 会导致耗时激增”的顾虑，本方案基于本地编译的 Fridrich 实验室原生 C++ STC 扩展（`pystcstego` 0.1.0），在 $1920 \times 1280$ 真实大图（总计 245 万个 DCT 系数）上进行了端到端实测（见 [`temp/stc_benchmark.py`](file:///c:/Home/Projects/strhide/temp/stc_benchmark.py)）：

| 性能与功能指标 | strhide 现有模式 (二元局部排序) | 学术标准模式 (全图三元置换 STC) | 差异与工程可行性判定 |
| :--- | :---: | :---: | :--- |
| **信道候选池规模 ($N$)** | 局部精选 ~30,000 槽位 | **703,351 个非零 AC 系数** | 覆盖全图全部有效交流系数 |
| **纯 STC 嵌入算法耗时** | ~20.4 ms | **1,937.9 ms (~1.94 秒)** | 状态转移计算量增加，但严格稳定在 2 秒内 |
| **纯 STC 提取算法耗时** | ~15.2 ms | **460.4 ms (~0.46 秒)** | 提取无需反向 Viterbi，仅做矩阵乘法，极快 |
| **端到端 CLI 嵌入总耗时** | 474.9 ms | **~2,400 ms (~2.4 秒)** | 包含读写 JPEG、DCT 变换与全图置换 |
| **盲提取逐比特还原率** | 100% PASS | **100% PASS (逐字节匹配)** | 100% 盲提取，零先验信息，绝对可靠 |

> **基准口径说明（重要）**：`temp/stc_benchmark.py` 的 100% PASS 验证的是 pySTC 在"候选池由调用方固定"路径下的正确性——`pystc/pystc.py` 的 `unhide()` 只做 reshape + shuffle + 解校验子，**不按 `|c|≥2` 规则重建池**。V3 生产提取链路是从 stego JPEG 重建池，两条路径不同；因此该基准**无法暴露候选池失步风险**（见 §三.3 边界规则与 §六 Phase 2 门禁），不得作为提取同步性的验收依据。

**工程可行性结论**：
对于命令行桌面工具（如 `strhide embed photo.jpg`），**单张数码照片 2 秒级的端到端处理耗时完全处于正常的人机交互体验区间**；换来的是消灭 $9\sigma$ 结构指纹、激活维纳极化与降低 15%~20% 改动率的核心安全性收益，**该架构在性能与工程上完全可行**。

## 三、STC-V3 核心算法与流程设计

```
                      ┌─────────────────────────────────┐
                      │    原始 JPEG 载体 (Cover JPEG)    │
                      └────────────────┬────────────────┘
                                       │ 读取频域 Y 通道系数
                                       ▼
                      ┌─────────────────────────────────┐
                      │    非零 AC 候选池 (nzAC Pool)     │  <-- 过滤: k != 0 且 |c| >= 2
                      └────────────────┬────────────────┘
                                       │ 密码派生确定性置换
                                       ▼
                      ┌─────────────────────────────────┐
                      │   全图置换序列 (Shuffled Slots)   │  <-- ChaCha12 + Fisher-Yates
                      └────────────────┬────────────────┘
                                       │ 结合三元代价 (UERD + 维纳极化打折)
                                       ▼
       ┌───────────────────────────────────────────────────────────────┐
       │             全图三元 STC Trellis Viterbi 求解器                │
       │  (前 128 槽嵌 Header，后续 K 槽嵌入 Payload 密文)               │
       └───────────────────────────────┬───────────────────────────────┘
                                       │
                                       ▼
                      ┌─────────────────────────────────┐
                      │    生成隐写载体 (Stego JPEG)     │
                      └─────────────────────────────────┘
```

### 1. 候选池构建（Non-zero AC Pool，消除超低载荷发散）
为了解决全图展开在极小载荷下可能导致的“修改点在全平滑区发散”的问题，建立严密准入规则：
* **排除 DC 系数**：每个 8x8 块的 $k=0$ 号系数绝对不入池；
* **排除零与极小值**：仅允许绝对值 $|c| \ge 2$ 的非零交流系数入池（对于平滑块，其大部分高频系数为 0，自然被隔离在候选池之外）；
* 候选池大小记为 $N$（在 $1920\times 1280$ 图像上，约为 50 万 ~ 75 万）。
* **参数语义**：V3 候选池仅由 `|c| ≥ 2` 规则决定，**不依赖代价阈值**；`wet_cost` 与 `block_exclusion_percentile` 对 V3 无意义（保留仅为 V2 兼容）。代价图在 V3 中只影响“改哪些槽”，不再影响“池有多大”，提取端与代价图完全解耦。

### 2. 密码确定性置换（Deterministic Shuffle Contract）
* 输入：密码经过 HKDF 派生的 `stego_key`；
* 发生器：严格复用项目已固化的 RFC 8439 规范硬编码 [`ChaCha12Stream`](file:///c:/Home/Projects/strhide/rust/src/stego/prng.rs#L85-L140) 与无偏拒绝采样 `Fisher-Yates` 洗牌算法；
* 保证：无论在任何操作系统或依赖版本下，相同密码对候选池生成的排列序列 100% 逐比特一致。

### 3. 三元代价与维纳极化无损接入
每个候选系数 $c_i$ 拥有三个合法转移状态：$\Delta c \in \{-1, 0, +1\}$。
1. **基础代价**：由 UERD 算法计算原始代价 $\rho_i$；
2. **截断残差估计**：解压缩 $\rightarrow$ 2D 维纳滤波 $\rightarrow$ 正向 DCT 估计连续波形系数 $C_{\text{estim}}$，计算截断残差 $e_i = C_{\text{estim}} - c_i$；
3. **真实三元极化打折**：
   $$w_{+1}(i) = \begin{cases} 0.65 \rho_i, & \text{if } e_i > 0 \\ \rho_i, & \text{otherwise} \end{cases}$$
   $$w_{-1}(i) = \begin{cases} 0.65 \rho_i, & \text{if } e_i < 0 \\ \rho_i, & \text{otherwise} \end{cases}$$
   $$w_{0}(i) = 0 \quad (\text{不修改})$$
   边界保护：若 $c_i = 1024$，则 $w_{+1} = \infty$；若 $c_i = -1024$，则 $w_{-1} = \infty$（避免推动已处极值的系数、减少直方图尾迹；提取端不使用代价图，该边界无需两端对称）。
4. **候选池不变性边界规则（盲提取同步的前提，正确性红线，不是可选项）**：
   * 若 $c_i = +2$，置 $w_{-1}(i) = \infty$；若 $c_i = -2$，置 $w_{+1}(i) = \infty$——即每个系数只允许“不跌破 $|c| = 2$”的方向；
   * **原理**：嵌入后所有池内系数仍满足 $|c| \ge 2$；池外系数永不被改动（$|c| = 0$ 不入池；$|c| = 1$ 只可能由 $|c| = 2$ 被 $-1$ 产生，已被上述规则禁止）。因此提取端按同一规则重建的候选池与嵌入端**严格同构**（规模与成员完全一致），全图置换序列不会错位；
   * **失效模式**：若缺少该规则，单个 $|c| = 2$ 系数被 $-1$ 改为 $|c| = 1$，即导致提取端池规模减 1，置换序列从该点起整体错位，Header 校验子读成乱码，**隐写数据全丢**。该失效无法被现有基准脚本暴露（见 §二 基准口径说明），必须以专门门禁测试守住（见 §六 Phase 2）。

### 4. 头部与消息布局
* **信道前 128 个置换槽位**：固定分配给 **V3 隐写头部**（32 比特载荷密文长度 + 32 比特校验魔数/FeatureWord，共 64 比特），以独立 STC 实例嵌入（$u=1$、$h=8$，与主体 STC 使用不同派生种子）；
  * 算术约束：相对码率 $R=0.5$ 下每槽仅承载 0.5 消息比特，64 槽只能装 32 比特——pySTC 的“前 64 槽”布局对应的是 32 位长度字段，**不适用于 64 比特头部**。按 `slots_for` 公式，64 比特头部在 $u=1,h=8$ 下至少需要 71 槽，取 128 槽（可承载 121 比特，留 57 比特余量）；
* **前 128 槽之后的 $K$ 个槽位**：分配给主体密文（采用 STC 约束高度 $h=8$，相对码率 $R = 1/2$ 或 $1/3$）。$K = \text{slots\_for}(\text{载荷比特数}, h, u)$ 由载荷精确决定，而非固定的 $N - 128$。

### 5. 提取端流程（毫秒级极速盲提取）
接收端流程彻底解耦：
1. 打开 Stego JPEG，按规则收集 $|c| \ge 2$ 的非零 AC 系数。候选池的规模与成员和嵌入端**严格一致**——这不是概率事件，而是由 §三.3 边界规则保证的不变量（改动不跌破 $|c| = 2$，池外系数也不会被带入池）。候选池同构是全图置换与校验子同步的前提，Phase 2 设门禁测试守住；
2. 依据密码派生种子，执行完全相同的 `ChaCha12` 置换；
3. 从置换后的序列中，直接计算校验子 $m = H x \pmod 2$：
   - 提取前 128 槽位 $\implies$ 解出载荷总长度 $L$（长度字段为明文嵌入，非加密）；
   - 提取后续 $K$ 个槽位 $\implies$ 提取出主体密文并完成解密；
4. **提取端耗时实测仅需 460 ms，且零图像代价计算，零算法失步风险！**

## 四、安全性与隐写抗检性收益评估

| 评估维度 | strhide 现有二元类桶模式 | STC-V3 标准三元置换模式 | 安全性增益机制 |
| :--- | :---: | :---: | :--- |
| **类边界单向门指纹** | **存在 $9\sigma$ 异常赤字** | **彻底消除 (0 赤字)** | 对称三元改动彻底消除单向门直方图萎缩 |
| **每比特改动率 (Embedding Efficiency)** | $\sim 0.250$ 翻转/比特 | **$\sim 0.20$ 翻转/比特** | 三元覆盖码数学效率提升，物理修改点减少 ~15%~20% |
| **DCTR 8000 维频域特征漂移** | 极化后反增 1%~5% | **预期有效压缩（待复测）** | 真正的方向选择使维纳连续补偿物理生效 |
| **PSNR 画质劣化** | -0.157 dB (明显降低) | **预期优于或持平（待实测）** | 补偿高频截断误差，更贴合连续波形 |
| **提取端实现复杂度** | 极高（需完整重算 UERD/几何） | **极低（纯矩阵乘法）** | 提取逻辑精简，彻底免疫浮点精度与分块对齐差异 |

> **表注**：
> 1. **改动率口径**：$\sim 0.25$（二元）/ $\sim 0.20$（三元）与类桶审计报告保持一致；绝对量级需按实际选用的 $h/u$ 重新推导（$h=8$ 的 STC 文献效率量级为 $1\sim2$ 比特/改动），实施时以 Phase 3 实测为准。
> 2. **“预期”项**（DCTR 漂移、PSNR）均为机制推断而非实测结论，已全部列入 Phase 3 验收门禁。
> 3. **失真 tradeoff（标准架构固有代价）**：全池置换 + 前 $K$ 槽意味着可改集合是“随机 $K$ 子集”而非“全局最便宜 $K$”（pySTC/HStego/J-UNIWARD 参考实现同理）。等载荷下失真可能略高于现有 V2 的代价 top-K 选槽，三元效率增益能否补偿需以 PSNR/改动点数实测判定。附带收益：正文槽位集合不再可被无密钥复算（`stego_hardening_final_plan_20261021.md` 记录的已知暴露由此消除）。

## 五、线格式向下兼容与迁移策略（Double-Track Design）

为了避免破坏现有已发布的 0.5.0 隐写载体，采用**双轨解码兼容策略**：

1. **版本识别机制**：
   * 提取端首先尝试按 V3 标准置换读取前 128 槽位；若解出有效的 V3 头部魔数，则进入 V3 极速提取流水线；
   - 若 V3 验证不通过，则优雅回退至现有的 V2 流程（在本地重算 UERD 能量并按类桶解调）；
2. **嵌入默认配置**：
   * 在初始发布阶段，默认开启 V3 标准三元嵌入；
   - 提供 CLI 参数 `--format-version v2|v3` 允许高级用户指定。

### 2. 定位澄清：学术界事实标准，而非“业界标准”

* STC 三元置换架构是 2011 年以来**学术界的事实标准**（WOW / UNIWARD / S-UNIWARD / J-UNIWARD / HILL / MiPOD 全线参考实现均为该配置，Binghamton stc 库 → pySTC / HStego / phasmcore 同构），在研究方法界具备基准可比性；但工业界工具（Steghide、OutGuess 等）并未达到此配置，对外表述建议统一使用“学术界标准 / 事实标准”，不用“业界标准”。
* **标准 ≠ 安全**。本方案的收益不来自“符合标准”本身，而来自解除类桶锁死后的三个可测后果：单向门统计指纹消失（$9\sigma$，独立评审 E2 级证据）、维纳极化方向选择真正生效、正文槽位集合不再可无密钥复算。抗检上限仍由代价函数质量与载荷率（bpp）决定，架构迁移只是拿全入场券。

### 3. 超出本期范围的议题

* **对抗式嵌入**：针对 CNN 隐写分析器（SRNet 等）的对抗样本式嵌入（项目 `temp/github` 下已有 CRoSS、Adversarial-Embedding 参考）是更远期的 P2+ 研究方向。若终极目标是对抗深度学习检测器，决定性变量是载荷率与代价函数，不建议塞进本期。
* **效率绝对量级**：§四 表改动率为量级口径，实施时按实际选用的 $h/u$ 重新推导，以 Phase 3 实测为准。
* **基准脚本加固**：`temp/stc_benchmark.py` 建议补充“从 stego 序列按 `|c|≥2` 重建池后再提取”的对照路径，使基准覆盖生产提取链路（当前基准结构上无法暴露候选池失步，见 §二 基准口径说明）。
